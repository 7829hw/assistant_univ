# RC6 빌드 계획(pilot_008 P4) — **만들지 않음, 선택지만**

RC6 = RC5 + batch011 승인분(결정 219). batch011은 아직 승인 전이라 아래 수는 "100건 모두 승인" 가정의 추정이다. 결정은 사용자(PLAN_DRAFT 7절 3번).

## 1. 바탕

| | 질문 | Full 레코드 | 비고 |
|---|---:|---:|---|
| RC5 | 391(상한 대상 340 + 예외 51) | 1,811(teacher full_response 763 + 8b json_only 1,048) | 모델 거부 target 0, 질문당 4.63 |
| batch011 r2(근접 대조 40) | +29(base 표본 중 초안과 같은 grounding이 있는 문항) | +103(질문당 8b 상한 4, J-b011 base 표본 일치분) | teacher 수집 없음 → 8b json_only만 |
| batch011 r1(거부 60) | +60 | 출처 선택(3절) | target `{"unsupported": true}` |

- r2 11문항은 base 표본 9개 중 일치가 0이라 레코드가 생기지 않는다(8b 정답 표본 출처만 쓸 때). 남는 문항에 teacher를 따로 모으려면 Ollama 27b 수집 결정이 필요(이번 범위 밖).

## 2. 유형 상한(결정 88·92)과 거부 칸

개발 분포(`pilot_prep_004/type_target`, 454문항)는 답하는 문항 5칸뿐이고 **거부 칸이 없다**. RC5 TV 0.0892(τ 0.09).

| 선택지 | r2 근접 대조 | r1 거부 | 결과(r2 40 기준 계산) |
|---|---|---|---|
| C-1 | 상한 안(새 문항 먼저, batch010처럼 칸별로 기존 문항을 밀어냄) | 상한 예외(결정 92식) | 상한 355 → r2가 칸 상한을 채우며 기존 25문항 정도가 밀려남, TV ≤ 0.09 |
| C-2 | 상한 예외 | 상한 예외 | RC5 + r2 전부: TV 0.1087(답하는 문항 기준, τ 초과 그대로 기록 — 결정 92 문구) |
| C-3 | 상한 안, 밀어내지 않음(남는 자리만) | 상한 예외 | r2 약 15문항만 들어감 |

- 거부 칸을 개발 분포에 넣는 대안: 개발 셋(selection_v2 7/98, valid98 5/98, aux 5/51, holdout 0/53 → 17/300 = 5.7%)을 기준으로 "거부" 칸을 더한 목표 분포를 새로 정한다
  (결정 88의 TV 계산 대상 변경 — 사용자 결정).

### 2.1 거부 비율 목표(레코드 기준)

N = RC5 1,811 + r2 103 = 1,914(거부 아닌 Full 레코드).

| 목표 | 거부 레코드 | r1 질문당 |
|---:|---:|---:|
| 5% | 101 | 1.7 |
| 8% | 166 | 2.8 |
| 10% | 213 | 3.6 |

질문 기준으로는 r1 60 / (391 + 29 + 60) = 12.5%(레코드 1개씩이면 레코드 기준 약 3%).

## 3. 거부 레코드의 출처(선택지)

J-b011(base greedy 1 + 표본 8, r1 60문항 540표본): **모델 거부 출력(`{"unsupported": true}`) 38표본·13문항**, 응답 grounding이 파이프라인에서 거부로 끝난 표본 69(28문항, 모델 거부 포함 107).

| 선택지 | 레코드 | 손실 범위 | 덮는 문항 | 주의 |
|---|---|---|---|---|
| S-1 base 올바른 거부 표본(모델 거부만) | base 원응답(thinking + `{"unsupported": true}`), 8b json_only와 같은 형식 | JSON만(5 token) | 13/60(상한 4 → 35레코드) | 범주가 고르지 않음(r1_forecast·r1_mode 거의 없음) |
| S-1' base "파이프라인 거부" 표본 포함 | 원응답 grounding(프로그램이 거부) | JSON(grounding, 중앙값 약 210 token) | 28/60 | (M) 문항에 grounding target — 계약상 (M)이 맞는 질문이라 **권하지 않음** |
| S-2 json_only 거부 target(teacher 없음) | thinking = 고정 짧은 근거(범주별 한 줄, 사람 검토) + `{"unsupported": true}` | JSON만(5 token) | 60/60 | thinking이 손으로 쓴 문장 — 손실은 JSON만이라 thinking 습관은 배우지 않지만 문맥은 학습 분포 밖 |
| S-3 S-1 + S-2 | 있는 문항은 base 표본, 없는 문항은 S-2 | JSON만 | 60/60 | 출처 표시(metadata `origin`) |

- 손실 비중: 거부 레코드 하나의 손실 token이 5개뿐이라(RC5 json_only JSON 중앙값 211.5, full_response는 thinking 포함 약 600), 8% 목표(166레코드)라도 거부 손실 token은 약 830 —
  전체 손실 token의 0.2% 안팎. 거부를 배우게 하려면 레코드 수를 늘리거나(질문당 여러 표본) 손실 가중(새 학습 옵션, 실행 의미 코드 변경 아님 — 학습 wrapper) 중 하나가 필요할 수 있다(선택).
- teacher(27b) 거부 trace 수집은 Ollama 사용·새 수집 결정이 필요해 이번 선택지에서 뺐다.

## 4. 검사(빌드 때)

- 거부 레코드: target이 정확히 `{"unsupported": true}`, T2PC 경로 `unsupported`, 길이 ≤ 12,288.
- 평가 셋·보호 셋 강한 겹침: 새 질문에 build6rc 규칙 + 거부 문항은 질문·Jaccard만. refusal_dev와 겹침 0(이미 검사).
- O4' 순서 파일: RC6 레코드로 새로 만든다(순서 seed 그대로, 질문 목록 sha256·공통 slot·연속 길이 확인).
