# `protected_final_v2` 명세(결정 220, pilot_008 준비 P6) — 초안

작성: 2026-10-22. **명세만 쓴다. 문항은 쓰지 않았고 볼 수도 없다.** 크기·분포·판정 규칙은 사용자 결정 전까지 선택지다(8절).
v1 명세(`pilot_006/protected_final_v1_SPEC.md`)를 바탕으로 하되, pilot_007 최종 판정에서 드러난 거부 문제와 겹침 검사 문제를 반영한다.

## 1. 목적과 사용 시점

- pilot_008의 채택 후보 **하나**를 base와 **한 번** 비교하는 최종 보호 셋. 정답률에 더해 **거부**(지원하지 않는 질문 거부, 지원하는 질문은 거부하지 않음)를 재는 것이 v1과 다르다.
- 측정 경로는 v1과 같다: PROTOCOL_v5(vLLM 0.30.0 BF16, flashinfer, LoRA 비병합, 동시 요청 8, `--max-model-len` 17,408, PROTOCOL_v4 3절 sampling), k=8, 한 번.
  실행 조건 위반으로 무효인 셀만 결과를 보기 전 이유를 기록하고 처음부터 다시(v1과 같음). 보정·재측정·부분 재사용 없음.
- 이 셋으로 checkpoint·arm·seed 선택, prompt·코드 수정, 학습 데이터 선택을 하지 않는다. 한 번 쓰면 끝난다(다음 판은 v3).
- pilot_008 작성 시작은 학습 전(결정 220). 고정(manifest 커밋)은 RC6 빌드 뒤(겹침 검사에 RC6 실제 학습 레코드가 필요 — 4.5절) 그리고 학습 결과를 보기 전.

## 2. 크기와 구성(선택지)

v1은 120문항 = 7유형 110 + 거부 10이었다. v2는 거부와 근접 대조의 비중을 올린다. **근접 대조**는 거부 문항과 겉모습이 비슷하지만 지원되는 질문으로 7유형 안에 든다(정답 호출 있음, 문항 메타에 표시).

| 선택지 | 전체 | 답하는 문항(7유형) | 그중 근접 대조 | 거부 | 정답률 95% 반폭(답하는 문항, k=8)* | +8%p 검정력* |
|---|---:|---:|---:|---:|---:|---:|
| V-a | 120 | 100 | 20 | 20 | 6.81(v1 분산 7.36) | 0.63 |
| V-b | 150 | 120 | 30 | 30 | 6.21(6.72) | 0.71 |
| V-c | 160 | 130 | 30 | 30 | 5.97 | 0.75 |

*정답률은 답하는 문항만(거부 문항은 거부율로 따로). 분산은 주 셋 151에서 F-o11 대 base 문항 차이(문항 간 0.105 + 표본 0.127/k)로 추정, 괄호는 v1 집계 반폭(6.72%p, n=120)에서
역산한 분산(`analysis/pf2_power.json`). pilot_007 F-o11의 v1 효과(+10.73)는 어느 선택지로도 잡히지만(검정력 0.89–0.94 at +11), +5%p 수준은 0.30–0.40.

거부율 반폭: `analysis/pf2_power.json`의 `refusal_projection`(refusal_dev 초안 셀로 문항 성분 추정, 6절 표에 옮김).

## 3. 분포 목표

### 3.1 의미 유형(답하는 문항, 정답 마지막 업체 tool 기준 7유형)

v1과 같은 비율 원칙(업체 100 사용 비중, 한 유형 6 이상)을 답하는 문항 수에 맞춰 다시 나눈다 — 예 V-b(120): 통과량 건수 22, 통과량 지표 18, 운행 지표 13, 통행 건수 26, 통행 지표 17, 요금 지표 17, 장소 이름(역방향) 7.

### 3.2 거부 문항(지원하지 않는 질문, 정답 = 거부)

- 범주를 고르게(`refusal_contract.md` 1절의 모델 거부 (M) 범주): 없는 지표, 없는 묶음 단위(week·month 밖), 개인·차량·기사·회사 단위, 예측(미래), 다른 교통수단, 도메인 밖.
  선택(사용자): 프로그램 거부 (P)형(계약 개념으로 적을 수는 있지만 계산할 수 없는 조합, 예: 결과를 쓰지 않는 조건) 문항을 일부 넣을지.
- 거부 범주마다 최소 3(V-a) / 4(V-b·V-c).
- 채점: 기존 파이프라인 결과 상태 — outcome ∈ {unsupported, needs_clarification}이고 분석 tool 실행 없음 → 올바른 거부(PLAN_FINAL 4절과 같음). 경로(M·P·C)도 함께 집계.

### 3.3 근접 대조(답하는 문항 안)

- 거부 범주마다 짝이 되는 지원 질문(예: 없는 지표 ↔ 목록 안 측정값, 분기별 ↔ 월별 bucket, 차량 단위 ↔ 택시 유형·지역 단위, 예측 ↔ 지난 기간, 버스 ↔ 택시, 도메인 밖 ↔ 장소 분석).
- 과잉 거부(거부로 끝난 표본)를 이 묶음과 답하는 문항 전체에서 따로 센다.

### 3.4 hard factor·난이도

v1 3.2·3.3과 같은 최소(답하는 문항 수 비례). 날짜 표현을 고르게, 기준일은 작성 시점에 정해 셋 메타데이터에 적는다.

## 4. 작성과 격리

### 4.1 작성자(v1과 같음)

- 문항은 보호 셋·이전 기록을 볼 수 없는 **새 대화**가 쓰고(업체 형식 문서·mock gazetteer·이 명세의 분포만 받음), **사용자가 검토**한다.
- Claude Code는 내용을 열지 않는다 — 기계 검사(validate, 겹침, 분포)를 **실행만** 하고, 보고는 수치·행 번호·코드만.

### 4.2 v1과의 관계

- v1에 쓴 **설계 구조(설계표 행·유형별 조합)를 그대로 다시 쓰지 않는다** — 새 설계표를 만든다. v1의 결과 수치는 크기 계산(2절)에만 쓴다. v1 문항·문항 단위 값은 보지 않는다.

### 4.3 설계표 규칙(v3 설계표 규칙)

### 4.5 검사(고정 전)

- `validate.py`의 형식·compile·mock·분포 검사.
- **겹침: `pilot_006/protected_final/validate_v2.py`**로 실제 학습 레코드까지 — `--train-jsonl`에 RC6 Full `sft_train.jsonl`, `--corpus`에 RC6의 승인 corpus(batch011 승인분 포함판).
  기준: 정규화 질문 같음 0, 문자 3-gram Jaccard ≥ 0.5 0, 같은 정답 grounding 0.

## 5. 판정 규칙(선택지)

- **정답률**(답하는 문항, PROTOCOL_v4 6절): 문항 쌍 bootstrap 10,000, `default_rng(20261109)`, 개선 = 정답률 차 CI 하한 > 0, U·조용한 오답 CI 하한 ≤ 0, 지연 ≤ 1.5배.
- 거부 조건(선택):
  - (J-a) 판정 범주 밖, 함께 보고(v1과 같음).
  - (J-b) 판정에 넣음: 올바른 거부율 차이(후보 − base) CI 하한 > 0 그리고 과잉 거부 차이 CI 하한 ≤ 0(늘지 않음).
  - (J-c) 판정에 넣되 비열등: 올바른 거부율 차이 CI 하한 ≥ −마진(예 −10%p) 그리고 과잉 거부 차이 CI 하한 ≤ 0.
- 정답률 개선과 거부 조건이 엇갈릴 때의 결론 범주(예: "정답률 개선, 거부 악화")를 고정 전에 정한다.
