# mock gazetteer 동명 시군구 문제(P9, 2026-10-16) — 기록만, mock은 고치지 않음

## 1. 문제

- `mock_responses.py`는 장소 이름을 키로 찾는다(`NAME_TO_FIXTURE`: `mock_stub.yaml` gazetteer의 이름·별칭 → fixture 하나).
  같은 이름의 시군구가 여러 시도에 있어도 이름 키는 하나뿐이다.
- 지금 gazetteer: `동구`·`중구`·`서구`는 **대구**의 시군구로만 있고, 부산 동구는 `부산 동구`라는 **별도 이름 키**로 있다.
- `get_place_scope(name=동구, region=부산)`: 이름으로 대구 동구 fixture를 찾은 뒤 `_region_matches`가 "부산"이 그 fixture의 조상(대구)이 아니라고 보고
  **NOT_FOUND**. 즉 스키마대로(상위 지역은 region) 쓴 부산 동구는 실행되지 않고, `name="부산 동구"`처럼 이름에 지역을 붙여야만 실행된다.
- `name=동구`(region 없음)는 언제나 대구 동구로 풀린다.

## 2. 영향 범위(`mock_same_name_scan.py` → `mock_same_name_scan.json`)

| 셋 | 문항 | 이름에 지역을 붙인 표기 | 동명·다른 지역(NOT_FOUND) | 동명·지역 없음(대구로 풀림) |
|---|---:|---:|---:|---:|
| selection_v1·v2, aux_test_v1, 업체 100, holdout | 100·98·51·100·53 | 0 | 0 | 0 |
| valid98 | 98 | 0 | 0 | 4 |
| 학습 v006_t2pc / pilot004 판 | 135 / 467 | 0 | 0 | 4 / 12 |
| 승인 corpus v2 | 580 | 0 | 0 | 8(trunk 4 + 같은 질문의 pg 4) |
| batch009 초안 84 | 84 | 2(b009-32 분류 밖으로 빠짐, b009-42 결정 139로 제외) | 0 | 0 |

- 보호 셋은 문항 수만 적었다. 지금 승인 데이터와 평가 셋에는 NOT_FOUND가 되는 문항이 없다.
- "지역 없음(대구로 풀림)" 문항은 질문에도 시도가 없다(예: "지난달 동구 법인택시 …"). mock에서 대구로 풀리는 것은 gazetteer의 기본 동작이고,
  질문이 실제로 어느 시도를 뜻하는지는 문장만으로 정할 수 없다. 이번 범위에서는 바꾸지 않는다.
- 이 문제 때문에 이제까지 빠진 후보: batch009 b009-42(결정 139). 앞으로 부산·서울·인천의 동구·중구·서구를 쓰는 후보는 모두 같은 이유로 실행되지 않는다.

## 3. 고칠 때의 영향

- `mock_responses.py`와 `mock_stub.yaml`은 실행 의미 지문(`execution_spec.code_fingerprint`, 현재 `791c4a68`)의 대상이다. 어느 쪽을 바꾸든 지문이 바뀌고,
  그 뒤의 평가 셀은 이전 기록과 같은 실행 조건이 아니게 된다(규칙: 결정 111 — Full 경로와 `SEMANTIC_CODE` 지문을 바꾸지 않는다).
- 고치는 방법 예: 이름 키를 (시도, 이름)으로 바꾸고 region으로 고르기, 또는 `부산 동구`를 `name=동구, region=부산`의 별칭으로 바꾸기.
  어느 쪽이든 (1) 지문 변경을 사용자 결정으로 받고, (2) base 셀을 새 지문으로 다시 재고, (3) `name="부산 동구"`로 쓴 기존 데이터(현재 0건)를 확인해야 한다.
- 권고: pilot_006 판정이 끝날 때까지 고치지 않는다. 새 후보를 쓸 때는 부산·서울·인천의 동명 시군구를 피한다.
