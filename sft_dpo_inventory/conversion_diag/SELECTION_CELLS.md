## 3. 결론

### 확인됨(이번 측정 기록에서 직접 확인)

- **Ollama 경로 안에서는 조건을 하나만 바꿔도 grounding_ok가 거의 같았다(±1). 그런데 문항은 21–31개씩 뒤바뀌었다.**
  - TEMPLATE, 변환, 양자화 쌍에서 순 변화는 −1에서 +1이다.
  - 같은 쌍에서 맞고 틀림이 바뀐 문항은 21–31개다.
- **U는 학습과 무관한 조건만 바꿔도 2–10 사이에서 움직였다.**
  - base 네 셀(E 7, c 2, B-conv 7, d 4)도 2–7로 갈린다.
  - 같은 학습 모델을 Q4_K_M에서 Q8_0으로만 바꿔도 10 → 3이다.
  - 학습 쌍의 U 변화는 Q4_K_M에서 +3, Q8_0에서 −1로 방향이 서로 다르다.
- **U의 구성은 셀 사이에 겹친다.**
  - n33(U1 taxi_status, 실차 통행량)은 Ollama 셀 6개 모두에서 U다.
  - 그다음으로 자주 나오는 것은 k27(dimension_target 누락, 4셀), g11(출발·도착 역할, 4셀), g02(실차, 3셀)다.
  - 나머지 U는 dimension_target 누락이 대부분이다.
- **Ollama 경로에서는 학습 모델이 base보다 grounding_ok가 5–6 높았다(Q4_K_M 69 → 75, Q8_0 70 → 75).** 두 쌍 모두 p ≥ 0.29다.
  - 같은 방향의 변화로 집계 추가가 줄었다(10 → 7, 15 → 6).
- **HF 경로에서는 같은 학습이 82 → 80이었다.** HF-base에는 처음부터 집계 추가가 4개뿐이었다.
- **HF BF16과 Ollama Q8_0은 같은 원본, 같은 렌더링(토큰 수 일치 10/10)인데도 base에서 82 → 70(5 / 17, p 0.017)으로 차이가 났다.**
  - 잃은 17문항 중 9개는 Ollama 출력이 질문에 없는 aggregation(sum 7, min 1, max 1)을 붙인 경우다. 그중 7개는 집계 말고는 차이가 없다.
  - 이 aggregation은 Ollama 기록의 plan 응답 원문(`llm_calls[].content`)에 그대로 들어 있다.
  - d가 집계를 붙인 12문항의 원문을 확인했다. 같은 문항의 HF 원문에는 11문항에서 aggregation이 없었다. 나머지 n02는 HF도 sum을 붙였다.
  - 즉 파이프라인 후처리가 아니라 모델 출력의 차이다.
- valid98의 기존 기록에서도 Ollama 경로(B-conv 48)가 HF base(55)보다 낮다. 다만 valid98에서는 HF-base의 집계 추가(20)가 B-conv(13)보다 많아서, 같은 원인으로 설명되지는 않는다.

### 가능성 있음(근거는 있으나 원인을 분리하지 못함)

- **이 셋(100문항, 한 번 측정)에서 셀 사이 U 차이 ±3–7은 학습 효과와 구별되지 않는다.** 학습과 무관한 양자화 수준만 바꿔도 7이 움직였기 때문이다.
  - pilot_002 업체 100의 운영 주 비교 "U 순증 6"(E 3 → Ollama-최종 9)도 같은 크기의 흔들림 안에 있을 수 있다.
  - 이번 작업에서 업체 100은 쓰지 않았으므로 확인하지 않았다.
- **Ollama 경로에서 학습이 grounding_ok를 올린 것은 주로 "질문에 없는 집계 추가"가 줄었기 때문일 수 있다.** valid98 HF에서 오른 이유(분석 문서 ANALYSIS.md)와 같은 모양이다.
  - HF-base selection에서는 집계 추가가 적어서, 줄어들 여지가 없었다.
- HF와 Ollama의 집계 추가 차이(4 대 10–15)는 Ollama base 네 셀 모두에서 나타났다. 원본(공식/직접 변환), TEMPLATE, 양자화 수준(Q4_K_M/Q8_0)과 무관하게 나타난다.
  - 따라서 BF16 → Q8_0 양자화보다는 HF 추론과 llama.cpp 추론의 차이(수치 경로 등)일 가능성이 있다.

### 미확인

- HF와 Ollama 출력이 다른 원인. 원인을 가르려면 모델 호출이 더 필요한데, 이번 작업에서는 하지 않았다. 남은 후보는 다음과 같다.
  - BF16과 Q8_0의 수치 차이;
  - torch와 llama.cpp의 커널 차이;
  - selection 문항에서 실제 입력 토큰이 같은지. 렌더링 확인은 주석 10문항의 토큰 수만 비교했다.
- Ollama 셀의 루프 여부(thinking 원문 미저장).
- 같은 셀을 반복 측정했을 때의 흔들림 크기. 이번 작업은 한 번 측정만 했고, Ollama temperature 0의 반복 일치 여부는 재지 않았다.
- 공식 가중치 위의 학습 효과((a)·(b) 미등록).
