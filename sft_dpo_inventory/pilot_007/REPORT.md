## 6. 배운 것

1. **데이터 정리는 줄 단위로**: 문제 문장이 있는 trace를 통째로 빼면 좋은 예까지 잃는다(RC3c → 개발 셋 −10 ~ −13%p). 줄 단위 편집(c2)으로 습관은 없애고 예는 지켰다.
2. **업데이트 양**: 1 epoch에서 lr 합이 0.034 → 0.181로 커질수록 좋아졌고, R1''(0.181)에서 75% 지점부터 평탄해졌다.
3. **순서 공유 규칙은 문구까지 확인**: 두 arm 순서를 같게 하려던 규칙이 질문 단위 배치를 만들어 한 arm만 크게 흔들었다. 공유는 slot 단위로(O4'), 학습 전에 연속 길이를 확인한다.
4. **seed 변동이 크다**: 같은 recipe·데이터·순서 분포에서도 순서 실현에 따라 주 셋이 ±4–8%p 움직였다(o43 A3 83.77 대 B2 75.66). 판정은 순서 seed 여러 개와 계층 bootstrap이 필요했다.
5. **사전 등록한 실행 규칙도 결과를 가를 수 있다**: 잘림 1% 다시 돌리기가 F 선행 하한을 −0.14 대 +0.04로 갈랐다. 경계 결과는 그대로 보고하고 사람이 결정했다.
6. **거부는 따로 지켜야 한다**: 학습 데이터에 모델 거부(`{"unsupported": true}`) target이 0개라, 1 epoch 학습 뒤 후보가 지원하지 않는 질문에도 답했다(4/80). 주·개발 셋에는
   모델 거부 유형 문항이 없어 이를 미리 잡지 못했다 → pilot_008(거부 보강 batch011, 거부 개발 셋 refusal_dev).
7. **보호 셋 겹침 검사는 실제 학습 레코드로**: validate.py가 승인 corpus v1만 봐서 RC5 질문 91개를 놓쳤다(76번 겹침) → `validate_v2.py`.
