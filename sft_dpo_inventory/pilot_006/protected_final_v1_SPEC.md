# `protected_final_v1` 명세(C10, 결정 106 D1)

작성: 2026-10-16(pilot_006 준비 세션 2). **명세만 쓴다. 문항은 쓰지 않았다.** 이 명세의 크기·분포·절차는 사용자 확인 전까지 초안이다.

## 1. 목적과 사용 시점

- pilot_006에서 F와 P 중 **채택 후보 하나**를 base와 **한 번** 비교하는 최종 보호 셋.
- 사용: 채택 후보가 정해진 뒤 base와 그 후보만 PROTOCOL_v5 경로(vLLM 0.30.0 BF16, flashinfer, LoRA 비병합, 동시 요청 8, PROTOCOL_v4 3절 sampling)로
  **k=8** 한 번 잰다. 판정은 PROTOCOL_v4 6절(문항 단위 쌍 bootstrap 10,000회, `default_rng(20261109)`, CI 하한 > 0이면 개선). 보정·재측정·부분 재사용 없음.
- 측정 장애(rule 13 같은 실행 조건 위반)로 무효가 된 셀만 처음부터 다시 잴 수 있다(결과를 보기 전, 이유 기록).
- 이 셋으로 checkpoint 선택, arm 선택, prompt·코드 수정, 학습 데이터 선택을 하지 않는다. 한 번 쓰면 `protected_final_v1`은 끝난다(다음 판은 `v2`를 새로 쓴다).

## 2. 크기: 120문항, k=8

근거: `protected_final_power.py` → `protected_final_power.json`. W8(`../pilot_006_prep/analysis/power.json`)은 F 대 P(비열등, 마진 −5%p) 검정력이고,
최종 판정은 **후보 대 base 우월**이므로 같은 방법을 실제 후보 대 base 차이 분포(pilot_005 v1_step467 대 vLLM base, selection_v2 98문항 k=4:
+11.22 [5.10, 17.86], 문항 차이 표준편차 0.33)에 적용했다. 문항 간 분산과 표본 안 분산을 나눠 k=8을 투영했다(k=4·98 반폭 재현 6.44 대 관측 6.38).

| 크기 | k | 95% CI 반폭(%p) | 우월 검정력 δ=5 | δ=8 | δ=11 |
|---:|---:|---:|---:|---:|---:|
| 80 | 8 | 6.32 | 0.34 | 0.70 | 0.93 |
| 100 | 8 | 5.65 | 0.41 | 0.79 | 0.97 |
| **120** | **8** | **5.16** | **0.48** | **0.86** | **0.99** |
| 150 | 8 | 4.61 | 0.57 | 0.93 | 1.00 |
| 100 | 4 | 6.38 | 0.34 | 0.69 | 0.92 |

- 120을 고른 이유: pilot_005 수준의 개선(약 +11%p)은 거의 확실히, +8%p는 0.86으로 잡는다. 150은 +8%p 검정력이 0.07 오르지만 작성·검토가 30문항(약 25%) 늘어난다.
  100은 +8%p 검정력이 0.79로 떨어진다.
- 가정: 새 셋의 문항 차이 분산이 selection_v2와 같다. 새 셋이 더 어렵거나 쉬우면(정답률 극단) 분산이 줄어 반폭이 좁아질 수 있고, hard factor 비중이 높아
  후보·base가 모두 흔들리면 넓어질 수 있다. +5%p 이하의 작은 개선은 이 크기로 판정 불가가 될 가능성이 크다(그때는 "판정 불가"로 보고).

## 4. 작성과 격리

### 4.1 작성자

- 결정 106은 "보호 셋을 보지 않고 새로 쓴다"를 요구한다. Claude Code는 이전 세션들에서 업체 100, selection_v1·v2, valid98, aux_test_v1, holdout을 읽었으므로
  **이 셋의 문항 작성자로 적합하지 않다.** 권고: 사람(사용자 또는 사용자가 정한 작성자)이 질문과 정답 설명을 쓴다.
- Claude Code의 역할은 작성된 문항의 **기계 검사만**(compile·mock 실행, 겹침 검사, 분포 집계) 한다. 문항을 고치자고 제안할 때는 문항 id와 검사 결과만 말하고,
  다른 보호 셋 문장을 근거로 들지 않는다.
- 대안(사용자 결정): Claude 초안을 허용하면, 보호 셋을 읽지 않은 새 세션에서 업체 형식 문서·mock gazetteer만 주고 쓰게 한다. 이 경우 출처를 셋 메타데이터에 적는다.

### 4.2 학습 파이프라인과의 분리

- 작성 중·고정 전 원본은 저장소 밖 `/home/hwkim/sftdpo_work/protected_final_v1/`(권한 700)에 둔다. 학습·teacher·자체 표본 수집 스크립트가 읽는 경로가 아니다.
- 저장소에는 `sft_dpo_inventory/pilot_006/protected_final_v1/`에 **manifest만** 커밋한다(4.3). 원문 gold는 최종 측정이 끝난 뒤 커밋한다.
- `build6.py`(학습 데이터 빌드)와 teacher·자체 표본 수집기는 이 셋의 질문과 정규화 문장, template, family를 **보호 목록**에 넣어 겹치면 빌드를 실패시킨다
  (세션 3에서 추가, 해시 비교라 원문을 저장소에 두지 않아도 된다: 정규화 질문 sha256 목록을 manifest에 둔다).
- 고정 뒤 이 셋으로 어떤 모델 출력도 만들지 않는다(smoke, 길이 측정, 렌더 확인 포함). 길이·렌더 확인은 질문을 넣지 않은 템플릿 길이로 대신한다.

### 4.3 해시 먼저 커밋

1. 작성·검토가 끝나면 원본 gold yaml을 고정하고, manifest를 커밋한다: 문항 수, 유형·factor·난이도 집계, 기준일, 원본 파일 sha256,
   문항별 정규화 질문 sha256 목록, 겹침 검사 결과(수치만), 작성자·검토자, 고정 시각.
2. 이 커밋 SHA가 "고정 시점"이다. 이후 원본이 바뀌면 sha256이 달라지므로 측정 전에 확인한다(다르면 측정하지 않고 보고).
3. 최종 측정 후 원본 gold와 셀 원문을 커밋하고, 측정 보고에 manifest 커밋 SHA와 sha256 일치를 적는다.
