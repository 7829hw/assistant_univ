## 3. 판정 설계에서 놓친 것

1. **seed 분산을 CI에 넣지 않았다.** 결정 154는 두 seed 표본을 한 arm으로 묶어 문항만 bootstrap했다. seed 주효과(sd ≈ 4.9%p)가 CI에 빠져 반폭 4.55가 실제(≈ 10.5)보다 작게 보였다.
2. **seed 2개로는 seed 효과의 크기를 알 수 없었다.** 세 번째 seed(s7)가 F에서는 s1016 쪽, P에서는 s43 쪽에 떨어져 "같은 seed P − F" 방향이 셋 중 둘에서 달랐다.
3. **F·P의 데이터 순서가 같은 seed에서도 달랐다**(레코드 수 1,861 대 1,826 → randperm이 다름). 순서가 정답률의 주된 원인이므로 arm 비교에 순서 잡음이 그대로 들어갔다.
4. **주 셋 holdout 53문항은 base가 이미 83%** — 학습 효과를 볼 여지가 작아 주 셋 판정이 selection_v2에 기울었다.

## 4. 데이터·teacher에서 놓친 것

1. **"결론" 문장**(결정 158 위험): 학습 모델 thinking의 56–77%가 입력에 없는 결론을 가리킴. 정답률과는 무관(문항 안 차 0)이지만 thinking 충실성 문제. RC3 teacher 레코드의 67%에 있었음. → `A2_CONCL.md`
2. **영어 생각**: RC3 teacher 레코드 약 18%가 영어 생각이었다(검사에 없었음). 학습 모델 e1 출력은 영어 0%였지만(base 100%), e2에서 4–7% 돌아옴. → `V3D_READ.md`
3. **v3d 지시**: "결론" 문장은 없앴지만(ii 0%) 영어 계획 + 한국어 초안의 2단계 생각을 유도(통과 trace 68% 영어). → teacher 검사에 (d) 한국어·(e) 영어 노출·메타를 더해야 함.
4. **P의 장소 빠뜨림**: P의 U 증가 대부분이 모델이 장소를 빠뜨린 것("<지역> 소속 택시", "…으로 들어온"). 학습 데이터에 "소속" 56문항이 있지만 teacher trace는 16개뿐. → `a3_u.json`

## 5. 잘 된 것

- 고정 → 학습 → 평가 → 판정이 계획대로 돌았고, 판정은 사전 규칙대로 "채택 없음"을 냈다(사후 마진 변경 없음).
- 순서 재구성(accelerate `SeedableRandomSampler`)이 로그와 정확히 맞아, `data_seed`로 순서만 바꾼 진단(2×2)이 가능했다.
- 학습 모델은 base의 repair·구조 오류 U를 없앴다(학습 모델 U에 구조·repair·거부 0). thinking 길이는 teacher 수준으로 줄었고 문항 안에서 정답률을 깎지 않았다.
- 효율(Gate E)은 seed와 무관하게 통과: P 지연 0.80, JSON token −34%.
