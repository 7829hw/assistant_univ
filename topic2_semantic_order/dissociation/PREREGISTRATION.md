## 3. X1·X2 — 답안 결정 지점의 로그 확률 (GPU, 추론만)

### 3.1 결정 지점

등록 전 확인(학습 데이터): V4 계획의 concept 직렬화 순서는 하나가 아니다. LOCATION이 첫 concept인 계획 1,255건(마지막이 아님), 마지막인 계획 403건,
concept 객체 키 순서도 `concept` 먼저와 `id` 먼저가 섞여 있다. 그러나 147문항의 기존 출력(18회, 분석 양식 2,421건)은 JSON으로 파싱되는 2,413건 중 2,410건이
`(AMOUNT, EVENT)` 또는 `(AMOUNT, EVENT, LOCATION)`이고(나머지 3건은 concepts가 빔, 파싱 실패 8건), 첫 객체 키는 `concept`가 먼저다. 그래서 결정 지점은 "EVENT 객체를 닫은 뒤 배열을 이어 가는가
닫는가"로 정한다.

- 적용 조건: 분석 양식 출력이고, 계획이 JSON으로 파싱되며, concepts의 concept 열이 `(AMOUNT, EVENT)` 또는 `(AMOUNT, EVENT, LOCATION)`인 출력.
  적용 비율을 실행별·합산으로 보고한다(등록 전 형식 조사 기준 2,410/2,421 = 99.5%).
- 자르는 위치: 원문 계획에서 EVENT 객체의 닫는 `}`를 찾고, 그 앞에 붙은 닫는 문자(`"`, `}`)의 연속 구간 시작에서 자른다.
  tail = 자른 곳부터 EVENT 객체의 닫는 `}`까지(예: `"}`, `"}}`).
  이유: Qwen3 tokenizer는 이 경계를 합친다(이어 쓸 때 `"},{"` 한 토큰, 닫을 때 `"}` + `],"` 또는 `]}`).
- 접두 = 평가와 바이트 단위로 같은 프롬프트 token id열 + 원문 `raw_text[:자른 위치]`를 같은 tokenizer로 토큰화한 열.
- **Δ = log P(이어지는 글이 `tail + ","`로 시작) − log P(`tail + "]"`로 시작).** 문자열 접두 확률은 모든 토큰화 경로를 더한다
  (토큰 trie를 따라 재귀; 디코딩이 남은 문자열의 접두인 토큰은 계속 내려가고, 남은 문자열을 접두로 갖는 토큰은 거기서 확률을 더하고 멈춤).
  logit은 온도 1, top-k/top-p 없이 쓴다.
- 보조: p₀.₆ = σ(Δ/0.6)(평가 온도 0.6에서 두 선택만 남긴 근사; top-p·top-k 절단은 무시), 이어 쓰는 분기에서 다음 concept가 LOCATION일
  로그 확률 log P(`{"concept":"LOCATION"` | 접두 + tail + `,`).

### 3.2 렌더링과 토큰 검증 (게이트, 실패하면 멈춤)

1. 프롬프트: 하네스(`sft_dpo_inventory/serving_vllm/vllm_thinking.py` `prompt_ids`)와 같은 `training.trainer_common.render_prompt` +
   같은 tokenizer(Qwen3-8B@b968826d)로 만든 id열의 `sha256(json.dumps(ids))`가 셀에 기록된 첫 계획 호출의 `prompt_ids_sha256`과
   **모든 (실행, 문항)에서 같아야 한다.** 하나라도 다르면 멈춘다.
2. 풀이 재토큰화: `raw_text` 전체를 재토큰화한 길이와 기록된 `generated_tokens`(끝 토큰 처리 규칙은 첫 확인에서 정하고 보고)가 같은 출력의 비율을
   보고한다. 다른 출력은 분석에서 빼고 수를 보고한다. 1% 넘게 다르면 멈추고 보고한다.
3. **AUC 검증**: 최종 18개 어댑터가 자기 풀이를 받았을 때의 Δ로 기록된 실제 방출(지표 2의 LOCATION 유무)을 맞히는 정도.
   통과 = 합산 AUC ≥ 0.80 **그리고** 실행별 평균 p₀.₆와 실행별 실제 방출률의 Spearman ρ ≥ 0.90.
   (기록 출력은 온도 0.6 표집이므로 AUC가 1에 가까울 이유는 없다. 실행별 AUC는 두 부류가 각각 10건 이상인 실행만 보고한다.)
   불통과면 X1·X2 해석을 멈추고 보고한다.

### 3.3 X1 — 자기 풀이를 받은 어댑터

- 대상: 기존 A/B 18개의 최종 어댑터(checkpoint-1984)와 같은 run의 중간 체크포인트 496·992·1488(54개, `/data/hwkim/sftdpo_work/{ablation_011,
  ablation_013,topic2_semantic_order,topic2_semantic_order_repro}/train/…`), 2단계 시작 시점에 완료 영수증이 검증된 B안 어댑터, X4의 새 어댑터.
- 중간 체크포인트와 B안 어댑터에는 147문항의 자기 H-dev 출력이 없다. 생성하지 않고(추론만), 중간 체크포인트는 **같은 run 최종 어댑터의 풀이**를,
  B안 어댑터는 **18개 run 모두의 풀이**를 받는다(X2의 답안 모델 자리). 이것은 "자기 풀이"가 아니라는 점을 결과에 표시한다.
- 가설 X1-H: 학습된 어댑터에서 빠뜨림은 풀이가 아니라 답안 결정 지점에서 정해진다. 판정 기준(숫자):
  풀이가 지역 조건을 서술한(보조 지표 참) 분석 양식 출력 가운데, 최종 어댑터의 자기 풀이 Δ < 0인 비율이 base(같은 풀이를 base가 받음, X2 base 행)의
  같은 비율보다 **20%p 이상 높으면** 지지. 같은 run 중간 체크포인트의 평균 p₀.₆ 궤적과 run 간 표준편차를 체크포인트별로 보고한다(기술).

### 3.4 X2 — 풀이 i를 어댑터 j에 (18×18)

- 풀이 작성자 i = 기존 18 run의 자기 출력(적용 조건을 만족하는 문항), 답안 모델 j = 같은 18개 최종 어댑터. 보조 행: base(학습 전) 답안 모델.
- 칸 값 M_ij = 풀이 i가 적용되는 문항에서 p₀.₆ 평균. 보조로 Δ 평균.
- 분해: 18×18 행렬의 2원 분해(행 = 풀이 작성자 주효과, 열 = 답안 모델 주효과, 나머지 = 상호작용). 제곱합 비중을 보고하고,
  95% CI는 문항 재추출 bootstrap 2,000회(`numpy.random.default_rng(20261116)`). 보조: 18 풀이 모두가 적용되는 공통 문항에서 문항 × 풀이 × 답안 3원 분해.
- 판정(숫자): 답안 모델 비중 ≥ 0.50 그리고 ≥ 2.5 × 풀이 작성자 비중이면 "답안 모델 주도", 반대(풀이 비중 ≥ 0.50 그리고 ≥ 2.5 × 답안 비중)면
  "풀이 주도", 그 밖은 "혼합". 판정은 점 추정으로 하고 CI를 함께 적는다.
- 연구 질문 2와의 연결(새 측정, 확인): 답안 모델 열 평균(M_·j)과 그 run의 지표 1(거절 풀이 비율, 기존 기록) 사이의 arm 안 Spearman 상관.
  |ρ| < 0.30이면 "따로 움직인다"를 지지, 그 밖은 지지 안 함. arm 사이(A 대 B) 차이는 별도로 보고한다.

## 5. X3 — 바꿔 쓴 탐침 (GPU, 생성)

- 탐침 (a): 질문의 `"(\S+) 소속 택시"` → `"\1에 등록된 택시"`(147문항 모두 한 번씩 해당). 탐침 (b): 질문의 "요금" → "수입"(모든 등장).

  ((b)는 측정값의 뜻이 바뀌므로 정확도가 의미 없다).
- 모델과 설정: 기존 18 최종 어댑터와 base. 하네스 `sft_dpo_inventory/pilot_005/vllm_eval_thinking5.py`, 원래 셀과 같은 표집 설정
  (온도 0.6, top-p 0.95, top-k 20, min-p 0, repetition 1, 회차 seed = 원래 셀과 같음; 어댑터 20261101, base s1·s2는 원래 셀 seed), 동시 요청 32.
  seed 규칙은 문항 id와 호출 번호에 따르므로 원문과 탐침의 seed가 같다.
- 비교: run마다 탐침 셀 − 원래 기록 셀(같은 어댑터). 정확 부호 뒤집기 검정(18 run, 2¹⁸ 전부 열거, 양측).
  - X3a 가설: "소속"이라는 말이 taxi_type 대응을 부른다. 지지 = 지표 2 차이 평균 ≥ +10%p 그리고 p < 0.05. 지표 3은 함께 보고.
  - X3b 가설: 학습에 없는 "요금"이 거절 풀이를 부른다. 지지 = 지표 1 차이 평균 ≤ −5%p 그리고 p < 0.05. 지표 2 변화는 탐색으로 보고.
  - base 행은 기술만. arm별 평균도 기술로 보고.
- 한계로 적을 것: 원래 셀은 다른 시각·GPU에서 쟀고, 같은 어댑터 재평가에서도 문항 불일치가 7.5–11.4% 있었다(스크립트 [4]).

## 6. X4 — "범위" 칸 데이터 변형과 학습 (데이터 CPU, 학습·평가 GPU)

### 6.1 데이터 변형 규칙 (4단계에서 만들고 사용자 승인 뒤에만 학습)

- 바꾸는 기록: V4의 `loss_scope = full_response`(teacher) 1,079건 중 분석 양식 풀이. `json_only` 905건, 시스템·사용자 메시지, 최종 JSON,
  그 밖의 모든 기록은 바이트 단위로 유지한다(검사로 확인). 기록 수와 순서 id는 바뀌지 않는다.
- 칸 추가: 풀이의 번호 목록(`5. 주변` 항목)이 있으면 그 항목 문단 뒤에 `6. 범위:` 문단을, 끝 요약 줄(`주변: …`)이 있으면 그 줄 뒤에 `범위: …` 줄을 넣는다.
  둘 다 없는 기록은 바꾸지 않고 수를 보고한다. 거부(`{"unsupported": true}`) 기록은 바꾸지 않는다.
- 칸 내용은 그 기록의 gold 계획(최종 JSON)에서 규칙으로 만든다. LOCATION concept가 있으면 각 장소를 (region이 있으면 "region name", 없으면 name)으로
  계획 순서대로 쉼표로 잇는다. 번호 문단 = `6. 범위: 장소 조건은 "<장소들>"이다.`, 요약 줄 = `범위: <장소들>`.
  LOCATION이 없으면 번호 문단 = `6. 범위: 장소 조건이 없다. 따라서 "지정 없음".`, 요약 줄 = `범위: 지정 없음`.
- "소속" 표현 고치기: "소속" teacher 기록 72건(스크립트 [5])에서 소속 지역을 "택시 유형" 조건이라고 부른 구절을 "소속 지역" 조건으로 고친다.
  **등록 전 확인:** 스크립트의 71건은 기록 어디든 "택시 유형"이라는 말이 있으면 센다. 72건에는 진짜 택시 유형(개인·법인택시)을 묻는 질문 38건과
  "날짜·택시 유형:" 소제목만 있는 기록 42건이 섞여 있고, 소속 지역을 "택시 유형" 줄에 적은 기록은 간이 분류로 약 15건이다.
  그래서 고칠 구절 목록은 4단계에서 구절 단위로 만들어 **사용자 승인 때 범위를 정한다**(71건 전부 대 지역을 택시 유형이라 부른 구절만).
  진짜 택시 유형(개인·법인) 구절은 고치지 않는다.
- 4단계 보고: 변형 규칙, 바뀐 기록 수(칸 추가·표현 고치기 각각), 손실 token 수 변화, 표본 20건 diff, 바이트 유지 검사 결과.

### 6.2 학습

- 설정: 무작위 순서 arm A의 기존 설정 그대로(V4, R1'', O4' 순서 파일, epoch 끝 checkpoint, thinking 켬, 87048d0c, `expandable_segments`).
  대조 = V4 원본, 처치 = 범위 칸 변형. 두 arm의 기록 id·순서 파일이 같다.
- 9쌍 = 순서 seed {1102, 211102, 2026131} × 학습 seed {43, 2026116, 2026119}(새 학습 seed 2개는 등록 전 `git grep -w` 0건).
  한 쌍(같은 순서 seed·학습 seed의 대조와 처치)은 같은 GPU에서 연달아 돌리고, 쌍 번호 홀수는 대조 먼저, 짝수는 처치 먼저.
  쌍 번호 = (순서 seed, 학습 seed)를 위 나열 순서로 행 우선 1–9.
- 시간이 모자라면 쌍 1–6만 하고 그 사실을 기록한다(6쌍이면 정확 검정의 최소 양측 p = 0.03125, 6쌍 모두 같은 부호일 때만 p < 0.05).
- GPU: 사용자가 Codex의 GPU 반납을 알린 뒤에만. CLAUDE.md 규칙 5·6·13, 결정 114(작업 하나 = GPU 하나, 커밋 고정 worktree, `gpu/timeline.jsonl`).

### 6.3 평가와 판정

- 평가: 최종 H-dev 2,000문항 k=1, seed 20261101, 동시 32(기존 H-dev 셀과 같은 하네스·설정). 새 어댑터에 X1 적용.
- **1차(확인)**: 대상 147문항 지표 2의 쌍별 차이(처치 − 대조), 정확 부호 뒤집기 검정(2⁹ = 512 전부 열거, 양측).
  지지 = 차이 평균 ≥ +10%p 그리고 p < 0.05.
- 2차: 요금 정확도(대상 147 match 비율) 쌍별 차이 평균과 같은 검정; 요금 외 정확도(1,829문항) 쌍별 차이 평균 — 평균 < −2%p이면 "퇴행"으로 표시;
  arm별 학습 간 표준편차(지표 2, 요금 정확도), 처치 SD ≤ 0.5 × 대조 SD이면 "흔들림이 크게 줄었다"고 적는다(기술, 검정 없음).
  지표 1·3, 처치 모델 풀이에 `범위` 칸을 쓰고 그 장소가 gold 장소와 같은 비율도 보고.
- 연구 질문 3 해석: 1차 지지면 "칸이 없어서 빠뜨린다"를 지지, 아니면 지지 안 함. 2차 SD 결과는 흔들림에 대한 기술로만 쓴다.

## 7. 멈춤 규칙

재현값 불일치, 렌더링 해시 불일치, 재토큰화 불일치 > 1%, AUC 게이트 불통과, GPU에 다른 프로세스, Ollama GPU의 `/api/ps`가 비지 않음,
이 등록을 바꿔야 할 때, X4 데이터 승인이 필요할 때. 결과를 본 뒤 지표·기준을 바꾸지 않는다.
