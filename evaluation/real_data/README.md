# 실제 질문·업체 계약 검증 준비

작성: 2026-10-05(grounding_v15).
- 지금까지의 GeoFlow 품질 수치는 mock provider·legacy 실행과 합성 문항(업체 100문항 외에는 Claude 작성, 사람 검토 없음)에서 나왔다.
- 이 디렉터리는 실제 질문과 실제 TIMS 응답으로 검증할 때 쓸 결정표와 입력 형식이다.
- 실제 자료는 아직 없다.

## 1. 지금 있는 것과 없는 것

| 항목 | 상태 | 근거 |
|---|---|---|
| 실제 TIMS 연결 | **없음** | `tool_handlers.get_tool_handlers`는 `mock`과 `reference`만 허용하고, 나머지는 오류로 막는다(mock으로 대체하지 않음). 저장소에 TIMS 주소·자격 증명·클라이언트가 없다 |
| 실제 TIMS 응답 자료 | **없음** | – |
| reference provider | 있음. **합성 데이터**(27행) | `reference_provider.py`, `evaluation/design/reference_provider.md`. 계산 경로 검증용이며 실제 데이터 검증이 아니다 |
| 실제 사용자 질문 | **없음** | 업체 100문항(`evaluation/vendor100/`)은 업체가 쓴 질문이다. 나머지 셋은 합성이다 |
| TIMS 계약 문서 | schema와 업체 prompt의 정의만 | `schemas/*.yaml`, `prompts/system.yaml`, README "업체 v2". 미확인 항목은 `evaluation/design/tims_lowering_contract.md` 2절 |
| 해석 결정 | 미정 | `decisions.md` D1–D4 |

mock·reference 실행을 실제 데이터 검증으로 대신하지 않는다. 입력 형식의 `provider.name`은 `tims`만 받는다.

## 2. 지금 확인할 수 있는 것과 외부 입력이 필요한 것

| 지금 저장소로 확인할 수 있음 | 외부 입력이 필요함 |
|---|---|
| GeoFlow가 보내는 Tool 호출이 schema 계약에 맞는지(validator·compiler, 테스트) | 실제 TIMS가 그 호출에 어떤 값을 돌려주는지 |
| 질문 원문이 실행 명세의 어느 조합으로 처리됐는지(CLI `geoflow_verification`·`geoflow_settings`) | 실제 질문이 무엇을 뜻하는지(검토자의 의미·기대 동작) |
| 계약상 표현할 수 없는 요구에서 멈추는지(지원 불가·확인 요청 경로) | D1–D4의 기본 해석, 동명 지명 처리 방침 |
| 합성 데이터 위의 계산 경로(reference provider) | TIMS 미확인 계약 항목(주 시작일, 부분·빈 구간, null, 상대 날짜 기준, 날짜 범위 끝, avg 분모, 날짜 귀속, 후보 목록 응답 형식) |

## 3. 입력 형식

`record_schema.json`(JSON Schema)이다. 한 줄에 한 질문을 적는 JSONL로 쓰고, `validate.py`로 형식을 검사한다.

| 부분 | 연결하는 것 |
|---|---|
| `question` | 실제 질문 원문(개인정보 제거), 질문 시각·시간대, **기준일**, 출처(real_user·service_staff·vendor) |
| `review` | 검토 상태, 검토자 역할, 검토한 의미, 기대 동작(answer·clarify·unsupported), 기대 호출, 버리면 안 되는 조건, **라벨 근거**(질문 명시·업체 계약·프로젝트 정책·업체 결정과 위치), 관련 결정(D1–D4) |
| `provider` | TIMS와 **계약 버전** |
| `run` | CLI 저장 기록의 `geoflow_verification`(검증 명세와 일치·다름·확인 안 함), `geoflow_settings`(기준일 포함), 기록 위치 |
| `actual` | 결과 종류, Tool 호출, 실제 TIMS 응답 원본 위치, 답변 |
| `comparison` | 분류(정상·조용한 오답·정확한 거부·부당한 거부·실패), 용납할 수 없는 실패·확장 요구 누락 종류, 값이 실제 응답과 맞는지 |

**규칙:**
- 비교 결과를 적으려면 검토가 끝나 있어야 하고, provider·run·actual이 있어야 한다.
- 업체 결정에 기댄 라벨은 결정 항목을 적어야 한다.
- 합성 문항은 이 형식에 넣지 않는다.

**실행 방법:**
- 기준일: CLI `--reference-date <question.reference_date>`로 실제 질문 시점과 같게 맞춘다.
- 모델 적재 상태: 실제 사용과 같게 연속 실행(CLI 기본)으로 둔다.
- 저장 기록의 `geoflow_verification`에 "다름"이나 "확인 안 함"이 있으면, 그 기록은 검증한 조합의 결과로 세지 않는다.

## 4. 필요한 표본 수 (판단 목표별)

표본 수는 판단 목표로 정한다. 정해진 문항 수를 채우는 것이 목표가 아니다.

| 판단 목표 | 필요한 규모 | 이유 |
|---|---|---|
| D1–D4 결정과 TIMS 미확인 계약 항목 확인 | 항목마다 몇 개의 대표 질문이나 대상 호출 | 통계가 아니라 사실 확인이다. 예: 주 시작일은 경계가 드러나는 기간 하나로 확인한다 |
| 용납할 수 없는 실패(조건 삭제·잘못된 scope·잘못된 측정 대상)가 드문지 | 0건일 때 95% 상한이 목표 비율 p 이하가 되려면 약 3/p | 5%면 약 60문항, 2%면 약 150문항, 1%면 약 300문항. 어떤 p를 받아들일지는 서비스 담당자가 정한다 |
| 정상 답변 비율을 추정 | ±10%p(95%)면 약 100문항, ±5%p면 약 400문항 | 비율이 50% 근처일 때의 최악 경우 |
| T2PC와 이전 기본 조합의 실제 질문 비교 | 같은 질문 쌍 수십 개 | 합성 자료에서 차이가 매우 컸다(정상 +18/56). 방향 확인은 수십 개로 되고, 정밀 추정은 위 비율 추정을 따른다 |

- 실제 질문은 실제 사용 분포에서 뽑는다(예: 기간·지역 무작위 추출). 실패할 것 같은 질문만 고르면 비율 추정에 쓸 수 없다.
- 검토 라벨은 두 사람이 따로 달고 불일치를 기록하는 것이 좋다. 한 사람이면 그 사실을 `review`에 남긴다.

## 5. 외부에서 받아야 할 입력 (구체적 요청 목록)

여기에는 목록만 둔다. 외부 담당자에게 보내지 않았다.

1. **업체 또는 서비스 담당자:** `decisions.md` D1–D4의 결정과 근거 문서.
2. **업체:** TIMS 계약 미확인 항목의 답(`evaluation/design/tims_lowering_contract.md` 2절 목록)과 계약 버전.
   - `get_place_scope`의 후보 목록 응답 형식도 포함한다.
3. **업체:** 실제 TIMS 접속 정보(주소·인증·호출 한도)와 시험용 범위.
   - 또는 GeoFlow 호출을 업체가 대신 실행해 응답을 돌려주는 방식.
4. **서비스 담당자:** 실제 사용자 질문 표본.
   - 원문, 질문 시각, 개인정보 제거 여부가 필요하다.
   - 받아들일 실패율 목표 p를 함께 정하면 4절에서 표본 수가 정해진다.
5. **검토자:** 표본마다 의미·기대 동작·라벨 근거(입력 형식 `review`).
