## 기존 실패 기록에서 확인한 원인 (C 실측 7개 셋 311문항)

1. **factor 재질의 문구의 집계 재사용 지침**("질문의 집계 표현이 이미 다른 조건에 쓰였더라도 … 구간별 값을 합치는 방식을 함께 뜻합니다"): 재질의 뒤 조용한 오답 3건이 모두 이 형태다(c08b, g44, t01c: 한 집계어를 aggregation과 rollup에 겹쳐 씀. 정답은 구간 안 집계 미지정 → 확인 요청).
2. **factor 재질의가 추가만 허용**: 재질의 실패 15건. 올바른 수정(answer 빼기, dimension 채우기)을 냈지만 기존 값을 되풀이하거나 빼서 `REPAIR_OUT_OF_SCOPE`로 거부된 것이 다수(007, m01, m04, c10a 등). 요일·지역 순위에 붙은 `answer=bucket`에 bucket을 채우라는 요청을 받아 `bucket=week`/`bucket=dayofweek`를 지어낸 것도 있다(065, n14, k19, g24, g33, k22).
3. **계획 단계 오류가 재질의에 닿지 않음**: grounding 계약(값 검사)에서 멈춘 `INVALID_FACTOR` 5건(015 bucket=dayofweek, k36, m17 rollup=top, m40 bucket=hour, 072 시간 형식)은 판정 없이 바로 실패로 끝났다. 합성 단계 오류만 재질의 판정을 받았다.
4. **기본 prompt의 짝 생략 지침**("짝이 되는 값을 읽을 수 없다면 둘 다 넣지 않습니다"): C와 재정렬 기준의 첫 응답에서 정답이 가진 짝 두 쪽을 모두 뺀 사례를 찾았으나, 이 지침 때문에 명시된 구간·집계 조건이 빠진 사례는 없었다(찾은 사례는 모두 rollup을 순위 자리에 쓴 자리 혼동). 실제 영향은 관측되지 않았지만 "질문에 있는 조건은 유지한다"와 모순이다.
5. `INVALID_ANSWER_TARGET`은 복구 대상이 아니었다(C 실측에서는 0건).

## 후보

- **R (복구 경로만, prompt 불변)**
  - factor 재질의를 factor 수정 재질의로 바꾼다. 결과 형태 factor(bucket, aggregation, rollup, answer, dimension, dimension_target, order, limit) 안에서 추가·변경·삭제(null)를 받는다. 기간·시간·택시 유형·운행 상태·장소 등 개념은 바꿀 수 없다(파서와 delta guard가 거부).
  - 지금과 같은 값을 되풀이한 것은 변화 없음으로 본다.
  - 재질의 문구에서 집계 재사용 지침을 빼고, 한 집계어는 한 단계에만 쓰며 구간 안 집계가 없으면 비워 둔다고 적는다.
  - `INVALID_ANSWER_TARGET`, 결과 형태 factor와 시간대의 `INVALID_FACTOR`도 같은 판정으로 재질의한다. 계획 단계(grounding 계약)에서 멈춘 오류는 첫 응답을 초안으로 삼는다.
  - 모델이 "질문에 없다"고 답하면 빠진 짝·답 대상은 사용자 확인, 계약에 없는 값은 지원 범위 밖으로 끝낸다.
  - 구간 안 집계 미지정(`AMBIGUOUS_INNER_AGGREGATION`)은 계속 재질의하지 않는다(모델이 집계를 지어내는 경로).
  - 재질의 횟수는 한 질문에 한 번 그대로다.
- **R+P**: R + 기본 prompt 짝 지침을 "질문에 있는 조건은 짝을 읽을 수 없어도 빼지 않고 적고, 빠진 짝을 지어내지 않는다"로 바꾼다.

## 측정

- **R: C의 첫 계획 응답 재생.** 기본 prompt가 같으므로 기록된 첫 응답을 그대로 쓰고 재질의만 실제 모델을 부른다. 재질의 직전에 모델을 내린다(격리). qwen3:8b, temperature 0, think auto, 기준일 2026-09-25, mock + TIMS legacy, 조건 계층 켬.
  - 복구 경로 변경의 효과(prompt 효과와 분리)다. temperature 0 결정성을 전제로 R의 전체 결과로도 쓴다.
- **R+P: 7개 셋 전체 격리 실측**(첫 응답부터).
- **같은 채점기(v3)로** `cad3bb8`·C·R·(R+P)를 비교한다. 정상 답변과 정당한 거부를 나눈다. 오답·부당한 거부·실행 실패, 재질의 횟수·성공, 문항 지연 합계·중앙값·p90을 함께 본다.
- **따로 센다:**
  - 집계 발명(정답이 구간 안 집계 미지정인데 aggregation이 채워져 실행)
  - answer 오용(구간이 아닌 순위·통계에 answer=bucket)
  - 재질의가 수정 범위 밖을 바꾸려 한 건수(거부됨)
  - 올바른 첫 grounding이 재질의로 바뀌거나 거부된 건수
- 정답 grounding → 실행기(`gold`)와 코드 단위 행동 검증(`tests/test_factor_correction.py`)은 모델 결과와 따로 보고한다.

- 7개 셋 맞음(정상 + 정당한 거부)이 C보다 낮지 않고, 조용한 오답이 C보다 늘지 않는다.
- 재정렬 기준 `cad3bb8` 대비 일반 질문 회귀(업체 100, 기존 44)를 구간 질문 성과로 상쇄했다고 보지 않는다. 셋별 차이를 그대로 보고한다.

- 연도 없는 날짜는 기존 확인 요청 정책을 유지한다.
