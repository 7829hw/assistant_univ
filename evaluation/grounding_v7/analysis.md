## 1. 계약인가, 보수적 복구 정책인가 (grounding_v6 제한 재검토)

| grounding_v6 제한 | 성격 | 이번 정리 |
|---|---|---|
| 두 단계 집계 값이 같으면 복사로 보고 막음 | **정책(의미 단정)**. "주별 최댓값 중 최댓값"처럼 정당한 질문을 막는다 | 값 비교를 없앴다. 같은 값 두 단계는 첫 grounding이 그 집계로 읽은 **같은 표현이 질문의 겹치지 않는 두 자리**에 있을 때 받는다(문자열 사실) |
| 집계 값 변경 금지 | 정책. 보고서는 "금지", 구현은 답 대상 위반에서 rollup을 아무 값으로 바꾸게 허용(불일치·위험한 예외) | 답 대상 위반의 rollup 변경을 "구간 선택 방향 max·min 다시 고르기"로 좁혔다. 원래 rollup 값은 aggregation으로 옮겨 보존하고, 새 방향 값은 근거 문자열이 필요하다. aggregation이 이미 있으면 answer 빼기만 연다 |
| 구간 안 집계 새 값 | 정책. 확인 불가 | 근거 문자열이 있어도 재질의로 받지 않는다(아래 2절). 실행하지 않고 구간 안 집계를 확인받는다 |
| rollup·answer → order·limit, 허용되지 않은 bucket → dimension | **복구 후보**(계약상 동치 아님). "주별 값 중 최대"와 "가장 큰 지역"은 같은 계산이 아니다 | `RECOVERY_CANDIDATES`로 이름을 바꾸고, 모델이 고르는 후보라고 수정 범위 근거에 적는다. 코드는 순위 방향(수정 전에 적혀 있을 때)과 그룹 존재만 지킨다 |
| `answer=value` 생략, 정수 문자열 | **계약상 같은 표현** | 코드가 적용(그대로) |
| 빠진 짝, 함께 쓸 수 없는 bucket과 dimension·order·limit, 답 대상 max·min | **계약** | 위반 정의를 `factors.contract_issues` 한 곳에 두고 검증(`validate_factors`)과 수정 범위가 같이 쓴다 |
| 범위 밖 조건 보존, 그룹·방향 보존, 새 구간·그룹 충돌 금지 | 불변식(코드가 확인할 수 있는 사실) | 그대로 |

**같은 제약의 다른 정의 정리:**
- 계약 위반 정의(검증·수정 범위)를 하나로 모았다.
- 구간과 함께 쓸 수 없는 factor(`EXCLUSIVE_WITH_BUCKET`)는 composer와 수정 범위가 같은 상수를 쓴다.
- 집계 값을 옮겨 받는 단계가 수정 가능 범위(`editable`)에 빠져 있어, 재질의 문구·파서는 허용하고 delta guard는 거부하던 불일치를 고쳤다.

## 2. 코드가 확인할 수 있는 사실과 없는 사실

| 경우 | 코드가 확인하는 것 | 확인하지 못하는 것 | 확인 실패 시 |
|---|---|---|---|
| 집계 값을 다른 단계로 옮김 | 값이 그대로 이어졌는가(버리지 않았나) | 그 값이 정말 그 단계의 표현인가 | (막지 않음) 이어진 값이면 적용 |
| 같은 값을 두 단계에 적음 | 같은 근거 문자열이 질문의 겹치지 않는 두 자리에 있는가 | 그 문자열이 그 집계를 뜻하는가 | 실행하지 않고 집계 단계 확인 요청(`AMBIGUOUS_AGGREGATION_STAGE`) |
| rollup 새 값(계약이 요구하는 짝) | 근거 문자열이 질문에 있는가 | 같음 | 같음 |
| 구간 안 집계 새 값 | 없음(근거 문자열과 값의 관계를 볼 수 없다) | – | 실행하지 않고 구간 안 집계 확인 요청(`AMBIGUOUS_INNER_AGGREGATION`) |

모델이 댄 근거는 의미의 증명으로 다루지 않는다. 시도 기록의 `evidence_check.note`에 "문자열이 질문에 있는지만 확인했다. 그 표현의 뜻은 확인하지 않았다"를 남긴다.

**중간 후보에서 실제로 뚫린 경로:**
- `c2a0e2c`, 대조 s01d("월별 수입의 평균"): 구간 안 sum을 지어내고 근거로 "월별 수입"을 적었다. 문자열이 있어 통과했고 조용한 오답이 됐다. → 구간 안 집계 새 값은 받지 않는다.
- `1b4a173`, t01c: 같은 값 두 단계의 근거로 서로 다른 문자열 "월별"과 "가장 큰 값"을 적었다. 겹치지 않는 두 자리라 통과했고 조용한 오답이 됐다. → 같은 문자열이어야 한다.

재질의 문구의 집계 단계·evidence 지침은 수정 범위가 집계 단계를 열 때만 보인다. `1b4a173`에서는 순위 복구 문구에도 이 지침이 들어가 있었고, 순위 복구 5건이 rollup을 남겨 실패했다.

**확인할 수 없어 끝나는 경우의 기록:** 확인 요청의 context에 `reason: repair_stage_value_unverified`, `clarify`(확정하지 못한 단계), 원래 계약 오류 코드(`from`)를 남긴다.

## 3. 행동 검증 (모델 없음, `tests/test_factor_correction.py` 외)

허용해야 할 수정과 막아야 할 수정을 모두 본다. 정상 grounding(첫 응답이 바로 맞음)과 계약 오류 초안의 복구를 함께 본다.

| 구분 | 허용(통과해야 함) | 차단·확인 요청 |
|---|---|---|
| 두 단계 같은 집계 / 한 단계 | 첫 grounding {week, max, max} 바로 실행. 초안 {week, max} + 같은 근거 "최댓값" 두 자리 → 실행 | 질문에 표현이 한 번뿐이거나 근거가 서로 다른 문자열 → 집계 단계 확인 요청. 첫 grounding {week, rollup max} → 구간 안 집계 확인 요청 |
| 단계 잘못 배치 / 미지정 | 첫 grounding {week, sum, avg} 바로 실행. 초안 {month, avg} → avg를 rollup으로 옮김 → 구간 안 집계 확인 요청 | 초안에서 sum을 새로 적으면 근거와 무관하게 구간 안 집계 확인 요청(정책 비용: 질문에 "합계"가 있어도 확인 요청) |
| 값 / 구간 | 값 질문 TIMS 실행. 구간 질문은 grounding 유효, TIMS는 `UNVERIFIED_TIMS_CONTRACT`, reference는 실행. 답 대상 초안 {week, rollup avg, answer bucket} → avg를 aggregation으로 옮기고 rollup max(근거) → TIMS는 provider 한계, reference 실행 | avg를 버리고 max만 적음 → 막음 |
| 역할 이동 / 조건 손실 | 요일 bucket → dimension, rollup → order(같은 방향), answer 빼기(순위·개수 보존), 007 dimension 채우기 등 11가지 | 순위 삭제(c06a), 방향 뒤집기, 그룹 전부 삭제, 범위 밖 변경·추가, 새 구간·그룹 충돌 |

- 정답 grounding → 실행기: 대조 셋 16/16. 7개 셋은 이전과 같다(grounding 계약·실행기 미변경).
- 전체 테스트: 1048개 통과(예상 실패 1).

## 7. 아키텍처와 복구 계약이 정리된 범위

- **코드의 역할:**
  - factor 계약 위반의 정의와 그 위반을 푸는 수정 범위를 계약에서 정한다.
  - 수정안을 범위 안에서만 적용하고 불변식을 확인한다.
  - 확인할 수 없는 새 값은 실행하지 않는다.
  - 질문의 뜻(어느 후보가 맞는가, 그 표현이 무엇을 뜻하는가)은 모델이 정하고, 코드는 문자열 존재와 구조적 사실만 본다.
- **변환의 구분:** 계약상 같은 표현(코드 적용)과 복구 후보(모델 선택, 동치 아님)를 나눴다.
- **실행 가능성:** grounding 계약상 유효성과 실행 가능성(TIMS 실행 계약, reference 직접 재계산)을 따로 판단한다. 업체 위임과 GeoFlow 직접 재계산의 검증 기준은 바꾸지 않았다.

| 정책 | 3 | 연도 없는 날짜(k01·k04·k16) |
| 제공자 실행 | 0 | 정당한 구간 질문은 정당한 거부로 셌다 |

**조용한 오답 29건의 차이 종류(정답 grounding 대비):**
- OD 끝 의미(장소 역할 pickup/dropoff/both, 결과를 묶는 끝 dimension_target): 11건(c04a, c04c, n03, n06, m10, m13, k25, k28, k31, k34, g11)
- 첫 grounding의 집계 지정(발명·누락): 7건(t02c, t05b, 021, n13, m24, k03, g23)
- 그룹 기준 누락: 3건(044, 046, g06)
- 순위 방향: 2건(m04, g16)
- 기타: 6건(운행 상태, 주변, 시간, 장소, 그리고 grounding 차이 없는 n31·m31)

**다음 개선 제안 (가장 영향이 큰 원인 하나): OD 끝 의미의 최초 grounding.**
- **영향:** 조용한 오답 29건 중 11건(38%)으로 가장 큰 단일 원인이고, 모두 형식상 유효해 검증·복구가 닿지 않는다.
- **근거:** 질문 "A에서 타서 B에 내린 운행을 내린 곳 기준으로"는 장소 역할(od_role)과 결과를 묶는 끝(dimension_target)이라는 두 관계를 함께 적어야 한다. 실측에서는 한쪽을 다른 쪽으로 옮겨 적거나(k25·k28·k31), 같은 지역 안 이동을 both로 적지 못했다(c04a·c04c·k34).
- **방향:** 복구 규칙이 아니라 grounding 계약의 표현과 prompt 설명에서 다룬다(예: 두 관계를 한 개념 아래 구분해 적게 하는지, 현재 표현으로 충분한지부터 정답 grounding 층으로 확인).
