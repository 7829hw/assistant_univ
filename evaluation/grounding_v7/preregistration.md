## 변경 (후보)

1. **집계 복사 판정을 바꾼다.** 기존에는 두 단계 값이 같으면 막았다. 이제 수정이 새로 적은 집계 값마다 모델이 질문에서 옮겨 적은 근거 표현(`evidence`)을 받고, 코드는 문자열 사실만 확인한다.
   - 그 표현이 질문에 있는가.
   - 두 단계에 같은 값을 적었다면 겹치지 않는 두 자리에 있는가.
   - 확인하지 못하면 실행하지 않고, 확정하지 못한 집계 단계를 확인받는다(`AMBIGUOUS_INNER_AGGREGATION` 또는 `AMBIGUOUS_AGGREGATION_STAGE`).
   - 값을 다른 단계로 옮기는 것은 근거가 필요 없다. 값을 버리는 것은 막는다.
2. **답 대상 위반의 rollup 변경을 제한한다.** "아무 값으로 바꿀 수 있음"에서 "구간 선택 방향(max·min)으로 다시 고르기"로 좁힌다.
   - 원래 rollup 값은 aggregation으로 옮겨 보존해야 하고, 새 방향 값은 근거가 필요하다.
   - aggregation이 이미 있으면 answer 빼기만 연다.
3. **변환을 둘로 나눈다.**
   - 계약상 같은 표현(코드가 적용): `answer=value` 생략, 정수 문자열.
   - 복구 후보(모델이 고름): rollup·answer → order·limit, 허용되지 않은 bucket → dimension, 집계 단계 옮기기, 짝 채우기, 방향 다시 고르기.
   - 복구 후보는 같은 계산이라고 가정하지 않는다.
4. **계약 위반 정의를 한 곳에 둔다.** 검증(`validate_factors`)과 수정 범위가 같은 `factors.contract_issues`를 쓴다. 집계 값을 옮겨 받는 단계도 수정 가능 범위(`editable`)에 넣어 문구·파서·delta guard가 같은 범위를 쓴다.
