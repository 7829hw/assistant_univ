# grounding 모델·계약 설명 비교 사전 등록 (grounding_v9)

작성: 2026-10-03. 선별 실측 전에 고정한다. 결과를 보고 바꾼 것은 끝의 "실행 기록"에 따로 적는다.

## 질문과 가설

- 목표: `geoflow/dev` 책임 분담을 유지한 채 v2 질문을 안정적으로 처리할 모델·계약 설명 조합을 찾는다.
- **가설 H-model:** qwen3:8b의 OD 혼동과 최초 grounding 오류는 모델 용량 때문이다. 같은 코드·prompt·평가에서
  설치된 더 큰 모델이 최초 grounding과 최종 결과를 개선하면 지지된다. 개선이 없으면 기각한다(확정된 원인으로 두지 않는다).
- **가설 H-desc:** 계약 설명(dimension_target 생략 = both, od_role과의 독립, 두 both의 차이)이 실행 계약과 어긋나서
  묶는 끝 누락이 생긴다. 설명을 정정하면 같은 모델에서 OD 결과가 개선되고 일반 질문은 회귀하지 않는다.
- 두 효과를 섞지 않도록 {qwen3:8b, 후보 모델} × {현재 설명, 정정 설명 D}를 같은 조건에서 잰다.

## 고정한 것 (모든 arm 같음)

- 코드: `geoflow/dev-v2` `67d727c`(= origin). 정정 설명 D는 `grounding-v9-desc` 브랜치 `70ca434`(아래)이고 그 밖은 같다.
- 아키텍처: LLM grounding → 조건 계층(--condition-check) → parse → composer → validator → compiler → executor.
  새 필드, 질문 정규식, 의미 덮어쓰기, 질문별·모델별 분기를 더하지 않는다.
- 재질의 예산 1회, 복구 정책(correction_scope), 제공자 위임·직접 재계산 검증 기준, 연도 없는 날짜 정책: 그대로.
- 생성 옵션: temperature 0만 지정한다. think 미지정(모델 기본; 측정 결과 모든 후보가 thinking을 낸다), num_predict 미지정,
  num_ctx 미지정(Ollama가 모델별로 정한 값을 기록한다), Modelfile 기본 파라미터(penalty 등)는 그대로 두고 기록한다.
  모델마다 다른 prompt·parser 관용·옵션을 쓰지 않는다.
- chat timeout 300초, planner 재시도 규칙(호출 실패·빈 응답·잘림만 1회 더) 같음.
- 격리: 문항마다 모델을 내리고 시작한다. 실측 중 다른 모델 호출을 하지 않는다.
- 환경: Ollama 0.34.4(docker, GPU 3번 RTX 6000 Ada 48GB 하나만 사용 가능), mock 제공자, 기준일 2026-09-25.

## 채점 (모든 비교 대상에 같게 적용)

- **v3(기존):** 그대로 보존하고 함께 보고한다. 기존 결과 파일은 바꾸지 않는다.
- **축별(v4-axes, `evaluate_vendor100.py axes`):** 저장된 관측만으로 계산한다(모델 호출 없음).
  - 의미: 최종 분석 호출의 Tool·인자·답변 값. 정답 장소는 정답 조회를 같은 실행기로 푼 scope와 비교한다
    (표기가 달라도 제공자가 같은 scope로 풀면 같은 장소). 주변 포함은 scope를 만든 조회의 값이 정답과 같아야 한다.
    정답이 조회 결과를 요구하는 인자의 scope는 이 run의 성공한 조회에서 나와야 한다. 분석 호출은 하나.
  - 경로: 장소 조회를 쓰임·실패·중복·폐기(성공했지만 최종 호출이 안 씀)로 나누고, 분석 호출 오류·정답보다 많은 조회를 센다.
    잘못된 장소 scope가 최종 호출에 쓰이면 의미 축에서 틀린다. 쓰이지 않고 버려지면 경로 축에만 남는다.
  - 비용: 계획·재질의 호출, 재질의 종류·실패, 문항 지연(합계·중앙값·p90·최대), 생성 토큰, 잘림, thinking 길이.
  - 기존 기록에 적용한 결과: v3와 달라진 문항은 실패·중복 조회를 버리고 맞는 장소를 쓴 것(n31, m31, m10)과 상위 지역
    표기만 다른 것(P2 dev/003, P5 m31, v8 held-out t29)뿐이다. 행동 테스트 `tests/test_scoring_axes.py`.
- **OD 층별:** trip 건수 문항마다 최초 원출력 → 형식 정규화 → 조건 보존 → 재질의 뒤 grounding → 실행 호출에서
  장소 끝(장소 scope × pickup/dropoff, od_role both는 두 끝)과 묶는 끝(dimension이 있을 때, 생략 = both)을 각각,
  그리고 둘 다 맞았는지 센다.
- 판단의 기본 결과 분류는 축별 채점이다. v3 숫자는 이전 단계와 이어 보기 위해 함께 적는다.

## 단계와 실행 범위

1. **탐침(정확도 아님):** 설치 모델마다 계획 요청 2개로 완료 여부·속도·context·VRAM·thinking을 본다.
2. **선별 S1(모델만 바꿈, 현재 설명):** 선별 96문항 × {qwen3:8b, qwen3.8:27b, qwen3.5:9b}. qwen3:8b는 기존 기록(`grounding_v7/runs_final`,
   `grounding_v8/runs/od_ecf323c`)과 같은 요청을 다시 재는 반복 측정이기도 하다.
3. **선별 S2(설명):** 선별 96문항 × {qwen3:8b, S1을 통과한 모델 최대 1개} × 설명 D.
4. **전체 F:** 개발 311 + OD 대조 16. qwen3:8b 현재 설명(반복 측정), 그리고 S1·S2를 통과한 조합만.
5. **held-out H:** 최종 후보와 qwen3:8b 현재 설명. 각 한 번.

후보 수 상한: 모델 후보 최대 3개(탐침에서 정함), 전체 실측까지 가는 조합 최대 3개(기준 반복 제외), 설명 문구 D 하나.
D가 탈락하면 새 문구를 만들지 않는다.

## 선별 통과 기준 (S1, 같은 96문항에서 qwen3:8b 재측정 대비)

- 축별 정상 답변이 기준보다 많고, 조용한 오답이 기준보다 많지 않다.
- 계획 호출 실패(timeout 등)로 끝난 문항이 96문항의 5% 이하.
- 문항 지연 중앙값 90초 이하(실사용 상한. 넘으면 정확도와 무관하게 이번 비교에서 제외하고 그 사실을 보고한다).
- 통과 모델이 여럿이면 정상 답변 → 조용한 오답 → 지연 중앙값 순으로 하나를 고른다.

## 채택 기준

기준 = qwen3:8b + 현재 설명. "반복 변동"은 qwen3:8b 현재 설명의 두 전체 실측(기록 `grounding_v7/runs_final`과 F의 재측정)의
축별 정상 답변 차이와 바뀐 문항 수다.

**모델 교체 (후보 모델 + 현재 설명):**
1. 개발 311 축별 정상 답변이 기준 F 재측정보다 max(3, 반복 변동)보다 많이 늘고, 조용한 오답이 늘지 않는다.
2. OD 대조 16 정상 답변이 기준 이상.
3. 새 held-out: 정상 답변이 기준 이상이고 조용한 오답이 기준보다 많지 않다.
4. 비용은 지연 합계·중앙값·p90, 재질의 의존도(정상 답변 중 재질의를 거친 비율), VRAM과 함께 보고한다. 지연 중앙값이
   기준의 몇 배인지 적고, 1–3을 만족해도 지연 중앙값이 60초를 넘으면 "정확도 개선은 확인, 실사용 비용 미충족"으로 판정한다.

**설명 정정 D (같은 모델에서 현재 설명 대비):**
1. OD: 개발 trip 문항(99)에서 실행 호출의 장소 끝·묶는 끝이 함께 맞은 수가 늘고, OD 대조 정상 답변이 줄지 않는다.
2. 일반: trip이 아닌 문항의 축별 정상 답변이 max(3, 반복 변동)보다 많이 줄지 않고, 전체 조용한 오답이 늘지 않는다.
3. held-out에 들어가면 OD 24 정상 답변이 현재 설명보다 낮지 않고 general 24 정상 답변이 2문항 넘게 낮지 않다.
- D는 모델마다 따로 판정한다(qwen3:8b에서 실패하고 큰 모델에서 통과할 수 있다).

**최종 판정:** 현재 모델 유지 / 모델 교체 / 설명 정정을 각각 위 기준으로 판정한다. 모두 미충족이면 현재 조합을 유지하고
결과와 다음 가설 하나를 남긴다.

## 보고 원칙

- 최초 grounding, 조건 보존 뒤, 재질의 뒤, 최종 결과를 나눠 보고한다. OD는 장소 끝·묶는 끝·둘 다를 따로 센다.
- 정상 답변, 정당한 거부, 조용한 오답, 부당한 거부, 실행 실패를 따로 센다. 거부가 늘어 오답이 준 것과 정상이 는 것을 구분한다.
- placebo(v8)는 문구 민감성의 보조 자료로만 인용한다. 선택된 문항의 변화율을 전체 변동률로 일반화하지 않는다.
- temperature 0을 완전한 결정성으로 가정하지 않는다. 같은 조건 재측정의 차이를 반복 변동으로 보고한다.
