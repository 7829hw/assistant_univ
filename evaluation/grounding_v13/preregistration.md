# 고정 후보의 제품 비교와 최종 채택 판단 (grounding_v13)

작성: 2026-10-05. **grounding_v11·v12의 결과를 본 뒤 설계한 별도 평가다.** 두 단계의 "사전 등록 기준 미충족으로 미채택" 기록은
그대로 둔다. 이번 평가는 그 기준을 다시 적용하는 것이 아니라, 실제로 쓸 조합의 전체 품질을 현재 기본값과 비교한다.

이 기준을 만들 때 이미 알고 있던 결과:
- B와 T2PC의 개발 428문항 결과(v9 full, v10·v11 운행 상태·held-out, v12 측정값 대조).
- T3PC의 136문항 결과(v12 작은 검증).
- qwen3:8b + T3PC 코드·prompt의 136문항 결과.

아직 모르는 결과:
- T3PC의 나머지 292문항.
- 최종 검증 셋 56문항의 모든 후보 결과.

후보를 통과시키려고 수치를 고르지 않는다. 결과를 본 뒤 기준을 완화하지 않는다.

이번 단계에서는 새 prompt 문구 후보, 새 grounding 필드, 정규식 의미 해석기, 추가 검증 모델 호출을 만들지 않는다.

## 4. 지표 (`report.py`)

- **분류:** v4-axes의 다섯 분류(정상 답변, 정당한 거부, 오답 = 조용한 오답, 부당한 거부, 실행 실패)이고, 채점 코드와 정답은 바꾸지 않는다.
- **용납할 수 없는 실패(U):** 평균에 묻지 않고 문항 목록으로 따로 센다.
  - U1: 요구 조건(장소 제한 외 date·time·taxi_type·taxi_status·그룹 기준, 지원 불가 문항의 required_condition)을 버리고 답함.
  - U2: 잘못된 scope·OD 끝·조회 출처·주변 포함으로 답함.
  - U3: 잘못된 Tool·metric(측정 대상)으로 답함.
  - U4: 질문에 없는 조건을 넣거나 조건 값을 바꿔 답함.
  - 집계·순위·개수·그룹 단위 차이는 조용한 오답에만 들어간다. "무엇을 셌는가"가 아니라 "어떻게 요약했는가"의 오류이기 때문이다.
    - 이 구분은 m05가 집계 문항이라는 것을 알고 정했다. 그래서 조용한 오답 총수도 그대로 기준에 넣는다(5절 E2).
- **지원 불가 문항:** 정확한 거부(측정값 맞음 + 조건 유지 + 멈춤 근거가 그 조건)와 조건을 버린 답.
- **조건 계층:** 잘못된 추가·삭제·놓친 채움.
- **측정값 오류 유형:** 반환 대상을 측정값으로, 통행량 → trip, trip → 통행량.
- **비용:** 지연 중앙값·p90, 재질의 호출, 실패한 LLM 호출(timeout).
- **같은 문항의 전환:** B → X 분류 전환 표와 문항 목록, 정상의 McNemar 정확 검정, 정상률 차이의 쌍별 부트스트랩 95% 구간.
  조용한 오답의 새로 생김·고쳐짐과 U의 새로 생김·고쳐짐도 함께 본다.
- **비율 구간:** Wilson 95% 구간.
- **정책 라벨 처리:** 조용한 오답은 정책 라벨(의미 모호) 문항을 포함한 값과 뺀 값으로 함께 보인다.

## 5. 후보 선택 규칙 (개발 428, B 대비)

X ∈ {T2PC, T3PC}는 다음을 모두 충족해야 최종 검증에 갈 자격이 있다. E1–E3은 정책 라벨 문항을 포함한 값과 뺀 값 모두에서
성립해야 한다.

| | 기준 |
|---|---|
| E1 | U 문항 수 ≤ B. 새로 생긴 U 문항은 모두 공개한다 |
| E2 | 조용한 오답 ≤ B |
| E3 | 정상 > B, 같은 문항 McNemar 양측 p < 0.05 |
| E4 | 정확한 거부 ≥ B, 조건을 버린 답 ≤ B |
| E5 | 지연 중앙값 ≤ 60초, 실패한 LLM 호출 ≤ 문항의 1% |

**둘 다 자격이 있으면 T2PC와 T3PC를 같은 문항으로 비교해 하나를 고른다.**
1. 조용한 오답의 차이가 유의하면(McNemar p < 0.05) 적은 쪽을 고른다.
2. 아니면 정상의 차이가 유의하면 많은 쪽을 고른다.
3. 둘 다 유의하지 않으면 다음 순서로 고른다: U 문항 수가 적은 쪽, 조용한 오답이 적은 쪽, 정상이 많은 쪽, 지연 중앙값이 낮은 쪽.

**중단:** 자격 있는 후보가 없으면 B를 유지하고 최종 검증을 돌리지 않는다. 최종 셋은 미사용으로 남긴다.

## 6. 최종 검증과 채택

고른 X와 B를 최종 56문항에 각 1회 돌린다. 다음을 모두 충족하면 X를 채택한다. 각 기준은 사전 점검에서 모호·의문으로 표시한
문항을 포함한 값과 뺀 값 모두에서 성립해야 한다.

| | 기준 |
|---|---|
| F1 | U 문항 수 ≤ B |
| F2 | 조용한 오답 ≤ B |
| F3 | 정상 ≥ B |
| F4 | 지원 불가 문항에서 조건을 버린 답 ≤ B |

- 56문항으로는 개선 폭을 정밀하게 추정할 수 없다. 최종 검증은 개발 판단이 보지 않은 문항에서 뒤집히지 않는지 확인하는 것이다.
  구간은 함께 보인다.
- **충족하지 못하면:** X를 채택하지 않는다. 최종 결과를 본 뒤 X를 고치거나 다른 후보를 고르지 않는다. 그렇게 하면 최종 셋은 독립
  검증의 지위를 잃고 개발 자료가 된다. 그런 일이 생기면 그 사실을 기록한다.
- **충족하면:** 다음을 반영한다.
  - X의 코드와 prompt를 dev-v2에 반영한다.
  - CLI GeoFlow 기본 모델을 qwen3.8:27b로 바꾼다.
  - README에 검증한 조합과 검증하지 않은 조합을 구분해 적는다.

## 7. 되돌리기·지원 범위 (채택하는 경우)

- **되돌리기의 정의:** 코드·prompt·기본 모델을 함께 되돌린다.
  - 채택 커밋을 `git revert`하거나, geoflow/·prompts/를 태그 `grounding-v12-baseline`으로 되돌린다.
  - 기본 모델은 qwen3:8b로 되돌린다.
- **실제 경로 확인:** `assistant_cli.py --agent-mode geoflow --query`로 다음 두 상태를 확인한다.
  - 채택 상태: 기본 모델과 `--model` 지정.
  - 되돌린 상태: 기본 모델.
  - 확인 내용은 머리말의 모델·출처, prompt hash, 그리고 고정한 6문항의 첫 계획 출력이다.
    - 6문항은 od/o01a·o02a, status/s01·s27, measure/m05·m13이다.
  - 평가 기록과 같은지 비교한다.
- **모델 이름만 바꾼 상태(qwen3:8b + X 코드·prompt):**
  - T3PC는 기존 136문항 기록(v12 q8_t3pc)을 쓴다.
  - T2PC를 고르면 같은 136문항을 1회 측정한다(`run_set.sh qwen3:8b q8_t2pc <T2C worktree> small`).
  - 이 조합은 문서에 "검증하지 않은 조합(회귀 확인)"으로 적는다.
- **사용자 지정 모델:** 존중한다(`--model` > `OLLAMA_MODEL` > 기본값). 문서에서 검증한 조합과 구분한다.
