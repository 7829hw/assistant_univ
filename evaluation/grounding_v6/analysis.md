## 1. 넓은 수정 범위를 어떻게 제한했나

**이전(`ee43487`):**
- factor 계약 오류 하나에도 결과 형태 factor 8개(bucket·aggregation·rollup·answer·dimension·dimension_target·order·limit)가 모두 열렸다.
- 수정안에서 빠진 것은 모두 삭제로 읽었다.
- 그룹 보존 guard는 bucket과 dimension이 모두 사라질 때만 막았다.

**지금(`geoflow/correction_scope.py`):**
- **수정 범위의 근거:** 오류가 난 grounding의 factor에서 계약 위반 전부(허용되지 않은 값, 빠진 짝, 답 대상)를 찾는다. factor 계약에서 factor별 허용 동작과 근거를 정한다. 질문은 읽지 않는다. 검증은 첫 위반에서 멈추지만, 수정 범위는 얽힌 위반(예: answer와 rollup이 함께 bucket 없이 있음)을 함께 본다.

| 대상 | 허용 동작 |
|---|---|
| 위반 factor | 뺄 수 있음. 허용되지 않은 값이면 값을 바꿀 수 있음 |
| 빠진 짝 | 새로 적을 수 있음. 단 주·월 구간과 함께 쓸 수 없는 그룹·순위가 남으면 bucket은 열지 않는다 |
| 뺄 수 있는 factor에 기대는 factor | 함께 뺄 수 있음 |
| 역할을 대신 적는 factor (비어 있을 때) | 새로 적을 수 있음: rollup·answer → order·limit, 허용되지 않은 bucket → dimension. 실측에서 모델이 자리를 혼동한 쌍만 둔다 |
| 새로 적는 factor의 짝 | 새로 적을 수 있음 |
| 집계 단계 배치 | 같은 값을 다른 단계로 옮기기만 됨 |

- **적용 규칙:**
  - 범위 밖 조건은 수정안에서 빠져도 남는다. 모델이 고친 뒤 전체를 적는 형식은 유지한다.
  - 범위 밖 조건을 다른 값·새 값·null로 적으면 수정안 전체를 받지 않는다. 코드가 일부만 적용한 혼합 계획을 만들지 않기 위해서다.
  - 집계 값은 새로 만들거나 바꿀 수 없다. 남아 있는 aggregation 값을 새 rollup에 복사하는 것도 받지 않는다(한 표현을 두 단계에 씀). 옮기기는 된다.
- **결과 역할 검사(계약 수준):** 그룹이 사라지거나, 순위 방향이 사라지거나 바뀌거나, 주·월 구간과 그룹의 충돌이 새로 생기면 받지 않는다.
  - 이것은 질문 의미의 증명이 아니다.
  - 순위 방향은 수정 전에 order나 rollup max/min으로 적혀 있을 때만 지킬 수 있다. 첫 grounding의 방향이 이미 틀렸다면(m04) 그대로 남는다.
- **기록:** 수정 범위와 근거, 수정 전·수정안·적용 뒤 결과 형태, 적용(추가·변경·삭제), 응답에서 빠졌지만 보존한 조건, 막힌 변경과 이유, 결과 역할 전후를 시도 기록의 `correction`에 남긴다.
- **재질의 문구:** 연 조건(허용 동작과 근거)과 그대로 남는 조건을 따로 보여 준다.

## 2. 평가 방식

| 방식 | 무엇을 보나 | 한계 |
|---|---|---|
| 기록 응답 재적용(`rerun`, 모델 호출 없음) | 이전에 기록된 수정안을 새 코드가 어떻게 처리하는가 | 재질의 문구가 바뀌었으므로 요청과 기록 응답이 대응하지 않는다. 모델 성능이 아니다 |
| 첫 응답 재생 + 실시간 재질의 | (이번에는 쓰지 않음) | grounding_v5에서 실제 실행과 모델 상태가 달라 관계 재질의 12문항이 달랐다 |
| 전체 격리 실측 | 채택 판단 | 재질의 출력은 실행마다 흔들린다 |

이후 기록에는 호출마다 요청 hash(`request_sha256`)를 남긴다. `rerun`은 요청이 기록과 같은지(`request_match`: same/changed/unknown)를 표시한다. 이번 재적용은 모두 이전 기록(hash 없음)이라 unknown이며, factor 수정 호출은 문구가 바뀌었으므로 "요청 변경"으로 본다.

## 5. 남은 한계

- **첫 grounding의 형식상 유효한 오답:** t02c·t05b·m24(집계 발명), m04(순위 방향). 계약 검사로 찾을 수 없다. 추가 검증 호출이나 새 의미 해석기는 만들지 않았다.
- **방향을 지킬 근거가 없을 때:** 수정 전에 방향이 없던 순위를 새로 적으면(k22: answer=bucket → order=top, 정답 bottom) 코드는 방향을 검사할 근거가 없다. 최종 실측에서는 범위 밖 rollup 추가로 막혔다.
- **집계 복사 금지의 비용:** "월별 평균의 평균"처럼 질문이 같은 집계어를 두 단계에 실제로 쓰는 경우, 수정으로는 표현할 수 없다(첫 grounding이 둘 다 적으면 영향 없음).
- **기본값 추가:** 범위 밖 `aggregation=avg` 추가는 기본값과 같아도 받지 않는다(065, R2 기록 1건).
- **유지한 정책:** 재질의 예산 1회, 기본 prompt 짝 지침 모순, 일반 질문 회귀(업체 100 89 vs `cad3bb8` 93, 기존 44 30 vs 36), 연도 없는 날짜 확인 요청 정책.
