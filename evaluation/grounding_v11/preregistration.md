# 조건 보존과 실행 가능성 판단의 책임 분담 사전 등록 (grounding_v11)

작성: 2026-10-04. 후보 실행 전에 고정한다. 결과를 보고 바꾼 것은 끝의 "실행 기록"에 따로 적는다.

## 목표

T1의 trip·OD 개선을 유지하면서 질문의 조건은 grounding에 보존하고, 실행 가능성과 멈춤 이유는 코드가 판단하게 한다.
기준을 충족하면 전체 평가와 보존된 v10 held-out까지 진행해 모델 교체를 결정한다.

## 출발점 (grounding_v10)

- T1(`grounding-v10-status` `5d39b37`, prompt 24df8c84): taxi_status 정지 27 → 1, OD 대조 16/16이었다. 그러나 taxi_status 의미의
  "받는 측정값은 통행량뿐 … 받지 않으면 지원 불가로 멈춘다"를 모델이 자기 판단 지시로 읽어 grounding 대신 unsupported를 냈다.
  지원 불가 7문항 중 정확한 거부(조건 보존 + 측정값 + 그 조건이 멈춤 근거)는 1(27b+D 6).
- s27: 모델은 상태를 적지 않았는데 조건 계층이 "실차 택시"로 occupied를 채워 멈췄다(prompt로 바뀌지 않는 코드 경로).

**설명 T2** (D 위):
1. [작업]: 질문의 측정값·장소·조건을 이 문서의 개념과 factor로 적을 수 있으면 실제 계산 가능 여부와 관계없이 그대로 적는다.
   계산 가능 여부와 멈출 이유는 프로그램이 판단한다. 계산되게 하려고 조건을 빼거나 바꾸지 않는다. unsupported는 해석할 수 없거나
   적을 수 없을 때만.
2. trip: 실차 구간은 손님을 태운 운행 한 번이고 그 자체가 실차다. 이 대상을 가리키는 "실차"는 taxi_status로 적지 않는다(T1 유지).
3. 통행량 혼동 쌍: 실차·공차·대기영업이 운행 상태를 고르는 말이면 taxi_status. 실차 구간을 세는 질문은 "구간"이 없어도 trip_count.
4. taxi_status 의미: 질문이 운행 상태를 요구하면 측정값과 관계없이 적는다. trip을 가리키는 '실차'는 조건으로 적지 않는다.
5. dimension 의미: bucket과 함께 쓰는 계산은 지원하지 않지만 질문이 둘 다 요구하면 둘 다 적는다.

**조건 계층 수정(코드)**: 조건 계층의 권한을 일반 규칙으로 정리한다.
- 질문 표현으로 조건을 **채우는** 것은 그 값이 측정값을 실제로 제한할 때다.
- 측정값 정의가 이미 고정한 값(operator 계약 `inherent_conditions`)은 채우지 않고 `not_filled`로 기록한다.
  - 계약상 고정된 값은 get_trip_count·get_trip_metrics의 taxi_status=occupied뿐이다(schema "실차 구간(trip)").
- 모델이 적은 값은 지우지 않는다.
- 공차·대기영업, Tool이 받지 않는 택시 유형은 지금처럼 채워 보존하고 합성이 그 이유로 멈춘다.
- 특정 문장 예외나 "trip이면 상태 삭제"는 없다.
- 행동 테스트: `tests/test_condition_authority.py`.
- 정답 grounding 재통과(gold-audit): 바뀐 것은 대조 s27·s28·s29의 잘못된 occupied 추가뿐이다. 개발 7개 셋은 0이고, 지원 불가 10문항의 조건은 그대로 남는다.

새 필드(grounding), Tool 직접 선택, 질문 정규식 추가, 조건 자동 삭제, 질문별·모델별 분기는 없다.

## 실행 기록

- **소규모(65):** T2PC가 통과 기준 1–6을 모두 충족했다.
  - taxi_status 정지 0, OD 대조 16/16, A 7·B 5·D 4·E 4·F 3/3.
  - 지원 불가 11 중 정확한 거부 10(s13 측정값 오독 1). 조건을 버리고 답한 문항 0, 모델이 낸 unsupported 0. 조건 계층 훼손 0.
  - prompt 효과(T1 → T2P): 정확한 거부 3 → 10, 모델이 낸 unsupported 8 → 0.
  - 코드 효과(T2P 기록 → T2PC 코드 재통과): 조건 계층의 잘못된 추가 3(s27–s29) → 0. 재통과에서 s28은 기록에 없는 장소 값
    재질의가 필요해 실패로 남았다(실측 T2PC에서는 정상).
  - **전체 평가와 held-out으로 진행한다.**
- **코드만의 효과(전체 범위, 모델 호출 없음):** v9 전체 기록 응답을 T2PC 코드로 다시 통과시켰다(`runs/rerun_code/`).
  - 27b+D 기록: 바뀐 문항 0.
  - qwen3:8b 기록: 2문항(dev/037 "실차 택시 통행량", old44/g04 "시군구별 실차 택시 통행량")이 "지원 불가로 멈춤"에서
    "답했지만 틀림"(조용한 오답)으로 바뀌었다.
    - qwen3:8b는 통행량 질문을 trip_count로 잘못 읽었다.
    - 기존 조건 계층은 "실차 택시"로 occupied를 채워 trip이 받지 못하게 했고, 그래서 오독이 **우연히** 거부로 끝났다.
    - 새 규칙은 trip의 정의값이라 채우지 않으므로 오독이 그대로 실행된다.
  - **판단에 넣는 제한(결과를 보기 전에 기록):** 조건 계층의 채움은 측정값 오독을 우연히 막는 효과가 있었다. 새 규칙에서 그 효과가
    사라진다. 측정값을 잘못 읽는 모델(qwen3:8b)에서는 조용한 오답이 늘 수 있다.
  - 채택 판단에서 T2PC 조합(qwen3.8:27b)의 전체·held-out에서 같은 경로(조건 계층 `not_filled`인데 정답에 그 상태가 있음 = 놓친 채움)가
    생기는지 보고, 사용자가 다른 모델을 지정할 때의 영향도 함께 판단한다.
- **지표 구현 수정(전체 결과를 본 뒤):** 거부 정확성의 첫 구현은 "기대 결과가 거부이고 정답 grounding에 taxi_status·taxi_type이
