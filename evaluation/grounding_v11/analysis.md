# 조건 보존과 실행 가능성 판단의 책임 분담 (grounding_v11)

- 사전 등록과 실행 기록: `preregistration.md`.
- **결론: 기본 조합을 바꾸지 않는다(qwen3:8b + prompt 522aa3b1).**
  - 최종 후보 T2PC(qwen3.8:27b + D + 설명 T2 + 조건 계층 채움 권한 정리)는 소규모 기준 6개, 제품 교체 기준 1–6을 모두 충족했다.
  - 그러나 직접 효과 기준 5(held-out 정상 ≥ 27b+D·T1)를 39 < 40, 1문항 차이로 충족하지 못했다.
  - 사전 등록대로 모든 기준을 충족해야 채택하므로 반영하지 않는다. 결과를 본 뒤 기준을 완화하지 않았다.
- 해결한 오류와 남은 제한은 아래와 같다. T2PC는 `grounding-v11-t2c`(`2f53c72`)에 보존한다.

## 1. 바로잡은 책임 분담

### 설명(prompt) — T2 (`grounding-v11-t2` `aa57c88`, prompt 87048d0c)
설명 전체에서 unsupported를 지시하거나 실행 가능성을 모델에게 넘기는 문장을 점검했다(`preregistration.md` 표).

| 위치 | 이전 | T2 |

해석 불가·표현 불가의 unsupported(측정값 없음, 출발·도착을 읽을 수 없음, 출력 형식)는 그대로 두었다.

### 조건 계층(코드) — 채움 권한 (`grounding-v11-t2c` `2f53c72`)
- **s27 경로:** 조건 계층은 "실차 택시"를 질문의 상태 표현으로 읽어, 모델이 적지 않은 `occupied`를 trip에 채웠다(모델의 맞는 해석을 훼손).
- **정리한 규칙:** 질문 표현으로 조건을 **채우는** 것은 그 값이 측정값을 실제로 제한할 때다.
  - 측정값 정의가 이미 고정한 값은 채우지 않고 `not_filled`로 기록한다.
    - operator 계약 `inherent_conditions`로 선언한다. 개수 Tool의 `inherent_reducer`와 같은 성격이다.
    - 지금은 schema가 "실차 구간(trip)"으로 정의한 get_trip_count·get_trip_metrics의 taxi_status=occupied뿐이다.
  - 모델이 적은 값은 지우지 않는다.
  - 공차·대기영업, Tool이 받지 않는 택시 유형은 지금처럼 채워 보존하고 합성이 그 이유로 멈춘다.
- 특정 문장 예외나 "trip이면 상태 삭제"는 없다. 질문 정규식은 더하지 않았다.
- **정답 grounding 재통과:** 바뀐 것은 대조 s27–s29의 잘못된 occupied 추가뿐이다. 개발 7개 셋 0, 지원 불가 10문항의 조건 보존 그대로.

## 5. 남은 제한 (판단에 포함)

1. **조건 계층 수정과 측정값 오독:** 기존의 상태 채움은 측정값 오독을 **우연히** 막는 효과가 있었다.
   - qwen3:8b가 "실차 택시 통행량"(통행량 + 실차)을 trip 건수로 잘못 읽으면, 기존 코드는 occupied를 채워 멈췄다(다른 이유의 거부).
     새 규칙은 trip의 정의값이라 채우지 않으므로 잘못 읽은 trip 건수로 답한다.
   - qwen3:8b 전체 기록 재통과에서 2문항(dev/037, old44/g04)이 이렇게 조용한 오답이 됐다. qwen3.8:27b 기록에서는 0이다.
   - 측정값 오독을 상태 채움으로 막는 것은 원래 근거가 틀린 안전장치다. 이를 없애면 오독이 드러나는데, 오독 자체는 막지 못한다.
     다른 모델을 지정해 쓰면 이 경로가 조용한 오답이 될 수 있다.
2. **"공차 운행/이동 건수"의 측정값 오독**(s13, v14): 27b 조합이 통행량 + 공차로 읽는다. 조건은 남지만 다른 이유로 멈춘다(정확한 거부 아님).
   단일 장소에 출발·도착 역할이 없는 질문이면 통행량으로 답할 수 있다(이번 셋에서는 관측되지 않음).
3. **장소를 측정값으로 읽는 오독**(dev/026·084, held-out v27): prompt 문구에 따라 나타나는 문항이 바뀐다.
4. **모델이 trip에 occupied를 직접 적는 경우:** 코드는 지우지 않으므로 그대로 멈춘다. T2로 이번 셋에서는 0이 됐지만 설명에만 의존한다.
5. **Tool 인자 검증에서 멈춘 지원 불가(k24):** 거부는 맞지만 분류가 실행 실패다.
6. 결과는 이 실행 조합(qwen3.8:27b `aaee06c3…` Q4_K_M, temperature 0, think 미지정, Ollama 0.34.4, 이 prompt·코드)의 효과다.
   모델 크기만의 효과나 다른 환경의 재현성은 주장하지 않는다. T2와 조건 계층 수정은 qwen3:8b에서 실측하지 않았다.

**모델 교체는 채택하지 않는다.**
- 제품 교체 기준은 모두 충족했고, 직접 효과에서도 조용한 오답·정확한 거부·trip·OD가 모두 나아졌다.
- 그러나 사전 등록한 직접 효과 기준 5를 1문항(v27, 측정값 오독에 의한 안전한 실패) 차이로 충족하지 못했다.
- 5절의 1번 제한(조건 계층 수정이 오독을 드러내는 경로)도 다른 모델 사용 시 조용한 오답의 위험으로 남는다.
- 판정이 1문항에 달려 있다는 점, 같은 셋에서 T2PC가 조용한 오답을 하나 줄였다는 점도 함께 기록한다.
