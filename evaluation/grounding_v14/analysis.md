# 운영 조건(모델을 올린 채 연속 처리) 검증: 결과 (grounding_v14)

작성: 2026-10-05.
- grounding_v13 채택 뒤의 별도 운영 조건 검증이다. 설계는 `preregistration.md`(e07ddd4, 실행 전 고정)에 있다.
- v13의 사전 등록 기준 충족과 채택 기록은 그대로 둔다.

**결론: 사전 등록한 운영 기준 OP1–OP4를 모두 충족했으므로 T2PC 조합을 유지한다.**
- 검증 범위에 "연속 실행(순서 3개, 56문항)"을 더했다.
- 검증 표시는 모델 이름에서 실행 명세 전체(digest·Ollama 버전·설정·provider)로 넓혔다.
- 새 prompt 후보·모델 탐색·질문별 예외·정규식 보정·근거 필드·추가 검증 모델 호출은 없다.

## 1. 출력 차이의 원인 분리

상세: `preregistration.md` 1절, `runs/diag/`.

**관측:**
- 평가 harness(문항마다 해제)와 CLI(연속 실행)는 같은 질문에 바이트 단위로 같은 요청을 보낸다.
  - 대상: system prompt·messages·options·think·stream.
  - 이전 질문·grounding·답변은 요청에 들어가지 않는다.
  - CLI는 질문마다 새 Runtime을 만든다. 테스트와 모든 요청 기록에서 누출 0이었다.
- 같은 요청이라도 서버 상태에 따라 응답이 달라진다.
  - 적재 직후의 첫 요청은 재현된다.
    - 진단 replay에서 내렸다 다시 보냈을 때 같았다.
    - 이번 C1이 v13 기록과 56/56 같았다(두 조합 모두).
  - 다른 요청을 처리한 뒤에는 달라질 수 있다.
- 서버가 보고한 `prompt_eval_count`는 항상 전체 prompt 길이였다. 캐시 재사용의 흔적은 보이지 않았다.
- 출력이 "직전 요청 하나"로만 정해지는 것도 아니다. B의 W1(파일 순서)과 W3(섞은 순서)은 직전 질문이 같은 문항이 1개뿐인데, 첫 계획 응답 원문이 44/56 같았다. 역순(W2)과는 7/56만 같았다.

**가설 (입증 안 됨):** Ollama/llama.cpp 서버 내부 상태(KV 캐시 슬롯·배치·커널 선택 등)가 이전 처리에 따라 남는다. 서버 내부는 조사하지 않았다.

**temperature 0의 의미:** 완전한 결정성을 보장하지 않는다. 같은 서버 상태에서만 같은 출력이 나왔다.

- **멈춘 사실과 바르게 해석한 사실의 구분:**
  - 멈춘 문항에서 최종 grounding의 측정값과 조건을 정답과 비교했다.
  - v13 개발 기록의 T2PC는 멈춘 52문항 중 8문항에 해석 오류가 남아 있었다.
    - v06: 날짜를 잘못 읽고 측정값 오독으로 멈췄다.
    - dev/026·084, k25, m07 등: 측정값 오독.
  - 이 운영 검증의 T2PC는 멈춘 11–14문항 중 1–4문항에 해석 오류가 남아 있었다(f01·f28·f02·f37의 측정값).
  - 거부 정확성(측정값 맞음 + 조건 유지 + 멈춤 근거가 그 조건)은 지원 불가 8문항 중 4회 모두 7이었다.
- **f03** (승차 기준 누락):
  - 조건 계층이 다루는 factor는 date·taxi_type·taxi_status뿐이다(`OWNED_FACTORS`).
  - 승하차 기준을 질문 원문으로 다시 읽던 코드는 2026-09-30 질문 재해석 제거(73b2206)로 의도적으로 뺐다.
  - 따라서 f03은 모델 grounding의 오류이고 조건 계층의 구현 오류가 아니다. 그 계층의 권한은 넓히지 않았다.
  - 운영 검증에서 f03은 해제 상태에서만 틀리고 유지 상태 3회는 맞았다. 서버 상태에 따라 나타나는 오류다.
