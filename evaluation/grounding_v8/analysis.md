## 1. OD 오답 11건의 실제 원인 (원출력 → 최종 호출)

grounding_v7은 OD 관련 오답을 11건으로 셌지만, 원출력부터 다시 보니 OD 혼동은 10건이다.

| 혼동 | 문항 | 원출력 → 최종 |
|---|---|---|
| **결과를 묶는 끝(dimension_target) 누락** | n06, k28 (장소 끝 = 묶는 끝); k31, k25 (장소 끝 ≠ 묶는 끝); m13, k34 (같은 지역 안 이동) | 생략 → 실행에서 schema 기본값 both(출발지-도착지 조합)로 묶임 |
| **같은 지역 안 이동(장소 od_role both) 누락** | c04a, c04c | 역할 없음 → 관계 재질의가 pickup을 고름 |
| | m13 | dropoff 하나만 적음 |
| **장소 조건 방향** | g11 | "초량동으로 들어온"을 pickup으로 적음 |
| | n03 | 역할 없음 → 관계 재질의가 묶는 끝(하차)을 장소 조건(dropoff)으로 옮김 |
| | k25 | 도착 장소를 both로 적음 |

- **OD가 아닌 m10:** 장소 역할은 맞았다. 질문에 없는 상위 지역("부산진구" + 부산)이 붙었고, 다른 장소의 조회 실패를 장소 값 재질의로 고쳤다. 답변 값은 맞다.
- **n31·m31(grounding_v7 분류 정정):** "29건 모두 최초 grounding 오류"는 정확하지 않았다.
  - 최종 호출 인자와 답변 값은 정답과 같다.
  - 첫 grounding의 장소 이름("두산동 도로", "진구")이 조회에 실패했고 장소 값 재질의로 고쳤다.
  - 채점기 v3는 실패한 첫 조회를 장소 조회 집합에 넣어 `place_lookup_count_ok`를 거짓으로 둔다.
  - 원인은 "최초 grounding의 장소 이름 + 실패 조회를 세는 채점 기준"이다. 이번 OD 변경에 섞지 않는다.
  - 실패한 조회를 오답 근거로 볼지는 채점 정책 결정으로 남긴다.

## 2. 표현 충분성과 계약 설명

- **표현:** 정답 grounding → 실행기로 OD 대조 셋 16문항이 모두 `match`다(`runs/gold_od_contrast.json`).
  - 장소 od_role(pickup·dropoff·both)과 dimension_target(pickup·dropoff·both·생략)은 서로 독립적으로 표현된다.
  - held-out 40문항도 정답 grounding으로 40/40이다.
  - **계약(필드) 변경의 실행 근거가 없어 바꾸지 않았다.**
- **모델에게 전달하는 설명의 불일치:**
  - dimension_target 의미 설명은 "질문에 승차나 하차 한쪽 기준이 없으면 넣지 않는다"고 하고 규칙 절도 "그런 표현이 없으면 넣지 않습니다"라고 한다.
  - 업체 schema에서 생략은 both(출발지-도착지 조합)다(`schemas/tims.yaml`).
  - 따라서 "생략 = 중립"처럼 읽히는 설명은 실행 계약과 다르다. 위 누락 6건이 모두 이 경로로 조합 결과가 됐다.
  - od_role both와 dimension_target both의 차이, 장소 끝과 묶는 끝이 다른 경우는 prompt에 설명이 없다.
  - **이 불일치는 남아 있다.** 고친 후보가 모두 채택 기준을 넘지 못했기 때문이다(3절).

## 4. 집계 정책의 실제 허용 범위 (grounding_v7 설명 정정)

- **설명과 구현의 불일치:** grounding_v7은 "구간 안 집계 새 값은 재질의로 받지 않는다"고 적었다. 그런데 구현은 두 단계가 같은 값이면 둘 다 새 값이어도 같은 값 두 단계 경로로 보냈다.
  - 예: rollup=top(허용되지 않은 값) 초안을 aggregation=max·rollup=max로 고치고 "최댓값"을 두 번 적은 경우
  - 이 경로로 구간 안 집계 새 값이 받아질 수 있었다.
- **정정(`9b1832f`):** 같은 값 두 단계는 첫 grounding이 이미 적은 값을 다른 단계에 한 번 더 쓰는 경우로만 좁혔다. `ecf323c` 실측 기록 재적용(요청 384건 동일)에서 결과가 바뀐 문항은 0이었다. 이 경로는 실측에서 쓰이지 않았다.
- **같은 문자열 두 번 검사의 성격:** 의미 검증이 아니다.
  - 같은 집계를 다른 표현으로 쓴 정당한 질문("주별 최댓값 중 가장 큰 값")은 확인 요청으로 끝난다(비용).
  - 반복된 무관한 문자열이 우연히 통과할 수도 있다.
  - 계약상 정답 조건이나 안전성 보장이 아니라, 코드가 확인할 수 있는 최소한의 문자열 사실이다.
- **실제 허용 범위:**

| 경우 | 처리 |
|---|---|
| 집계 값 옮기기 | 근거 없이 받음 |
| 첫 grounding 값의 같은 값 두 단계 | 같은 문자열이 겹치지 않는 두 자리에 있을 때 받음 |
| rollup 새 값 | 근거 문자열이 질문에 있을 때 받음 |
| 구간 안 집계 새 값(두 단계 모두 새 값 포함) | 받지 않고 확인 요청 |

## 7. 남은 문제와 다음 단계 제안

- **최초 의미 추출:** trip 질문의 최초 grounding 의미 정확이 34/99(개발), 새 문장 OD 정상 답변이 10/30(held-out)이다. 남은 OD 문제의 대부분은 계약 표현이 아니라 최초 의미 추출에 있다.
- **계약 설명:** dimension_target 생략 = both를 모델이 모른다. 설명 불일치가 그대로 남아 있다.
- **평가 수단:** qwen3:8b는 뜻 없는 문구 변경에도 첫 grounding 대부분이 바뀐다. prompt 한 번의 변경으로 특정 의미를 고르게 개선하기 어렵고, 효과를 보려면 placebo 대비 측정이 필요하다.
- **다음 개선 제안:**
  - **원인:** 최초 OD 추출의 모델 용량·안정성이다. 근거는 placebo만으로 첫 계획 82/92 변동, trip 최초 정확 34/99, held-out OD 10/30이다. prompt 설명 개선은 세 번의 실측에서 일관된 순이득을 내지 못했다.
  - **방향:** 같은 prompt 522aa3b1과 같은 평가(대조 셋, 개발셋, held-out)로 더 큰 grounding 모델을 비교한다. 아키텍처와 계약은 그대로 두고 모델만 바꾸는 측정이라 책임 분담을 건드리지 않는다.
  - 설명 불일치(생략 = both)는 그 모델에서 다시 측정해 고친다.
