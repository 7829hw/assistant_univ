# 조건 계층 공통 코드와 측정값 추출 (grounding_v12)

- 사전 등록과 실행 기록: `preregistration.md`. 기준은 grounding_v11 결과를 본 뒤 만들었고, 새 최종 검증 결과를 보기 전에 고정했다.
- **결론: 채택하지 않고 종료한다. 기본 조합(qwen3:8b + prompt 522aa3b1 + `geoflow/dev-v2` 코드)을 유지한다.**
  - 두 후보(T3P, T3PC)가 모두 작은 검증 기준 K1을 충족하지 못했다.
  - 사전 등록대로 전체 평가, 최종 검증, 되돌리기 검증은 하지 않았다.
  - 새 최종 검증 셋(56, sha256 `1afabe14…`)은 쓰지 않은 상태로 남는다.
- grounding_v11의 미채택 기록은 바꾸지 않았다.

## 1. 조건 계층 변경: 보장하는 사실과 모델에 의존하는 전제

| 구분 | 근거 | 관측 |
|---|---|---|
| 코드가 보장하는 사실 | schema상 trip Tool은 실차 구간만 다룬다. 측정값이 trip이면 occupied는 제한을 더하지 않는다. 모델이 적은 값은 지우지 않고, 받지 않는 조건(공차·대기영업·택시 유형·그룹 기준)은 그 이유로 멈춘다 | 행동 테스트, 정답 grounding 재통과(바뀐 것은 s27–s29의 잘못된 추가뿐) |
| 모델 해석에 의존하는 전제 | 측정값을 trip으로 고른 것이 맞다 | 코드는 확인할 수 없다 |
| ① 최초 측정값 오독 | 통행량 질문을 trip으로 읽음 | qwen3:8b: 개발 7, 이번 작은 검증 4(기준)·5(T3PC 코드·prompt). 27b: 모든 조합 0 |
| ② 정당한 중복 조건 생략 | trip을 맞게 읽은 "실차 택시가 태운 손님"류에 occupied를 채우지 않음 | 27b + T3: T3P 기록을 T3PC 코드로 재통과하면 m17·s27–s29가 거부에서 정답으로 바뀐다(s28은 재통과에 기록에 없는 재질의가 필요). 거부에서 오답으로 바뀐 문항 0 |
| ③ 변경 때문에 ①이 실행까지 간 영향 | ①이 occupied 표현과 겹치면 기존 코드는 잘못 채운 occupied로 우연히 멈췄고, 새 코드는 잘못 읽은 trip으로 답한다 | qwen3:8b 기록 재통과: 2문항(dev/037, old44/g04). qwen3:8b + T3PC 실측: 놓친 채움 3(m13·m14·m16)이 모두 조용한 오답 |

- 기존의 잘못된 추가를 안전장치로 되살리지 않았다. 질문별 예외, 정규식 의미 보정, 모델명 분기도 두지 않았다.
- **판단:** 이 변경은 측정값 추출이 안정된 모델과 함께일 때만 안전하다. 그래서 공통 코드로 단독 채택할 수 없고, 모델·prompt·코드를
  한 조합으로만 채택할 수 있다. 관측 범위에서 qwen3.8:27b 조합에는 ③이 0이다. 다만 관측이지 보장이 아니다.
- **되돌리기:**
  - 모델 이름만 바꾸는 것은 충분하지 않다. qwen3:8b + T3PC 코드·prompt는 작은 검증 136문항에서 조용한 오답이 기준 조합 12 → 18이다.
  - 코드·prompt를 기준 태그 `grounding-v12-baseline`(`d2580a5`)으로 함께 되돌려야 한다.
  - 채택하지 않았으므로 이번에 기본 경로를 바꾸지 않았고, 되돌리기 실측도 하지 않았다.

## 2. 측정값과 반환 대상의 혼동

- **원출력:** dev/026·084, k25, m18, v06·v27(T2PC)
  - 그룹 기준(dimension·dimension_target)과 순위(order·limit)는 맞다.
  - 반환 대상 장소("어디", "상위 2곳", "곳")를 MEASURE(LOCATION/place)로 두고, 세어야 할 값을 빠뜨렸다.
- **설명의 원인:**
  - MEASURE의 정의가 "질문이 구하려는 값"이었다.
  - "구하려는 값이 장소명일 수도 있다"는 문장이 있었다.
  - 유일한 "어디" 예시가 scope 이름 묻기(MEASURE = LOCATION/place)였다.
- **현재 표현은 충분하다.** 무엇을 세나(MEASURE), 제한 조건(장소·factor), 묶는 기준(dimension·dimension_target·bucket),
  반환 대상(값 / order·limit로 고른 그룹 / answer=bucket / scope 이름)으로 대조 셋 18문항을 모두 정답 실행기에서 확인했다.
  새 필드는 두지 않았다.
- **설명 T3**(`grounding-v12-t3` `5178481`, prompt ad73099b):
  - MEASURE를 "세거나 집계하는 값"으로 정의했다.
  - 질문의 네 부분을 현재 표현에 대응시켰다.
  - LOCATION/place MEASURE는 주어진 scope의 이름만 물을 때뿐이라고 적었다.
- **효과(작은 검증 136문항, 첫 출력):** 반환 대상을 측정값으로 읽은 경우가 T2PC 7 → T3 0이다. 같은 136문항에서 T2PC가 틀리고
  T3PC가 맞힌 문항은 dev/026·084, k25, m18, v27, m07, m09다.
- **같은 원인 가설(통행량 → trip):** 지지되지 않는다. T3는 qwen3:8b의 통행량 → trip을 줄이지 못했다(4 → 5).
  두 오류는 나타나는 모델과 형태가 다르다.

## 4. 무엇이 막았고 무엇이 더 필요한가

**막은 것:** 사전 등록 K1(측정값 대조의 조용한 오답 0)을 m05 한 문항이 막았다. 하지만 한 문항의 문제가 아니라 반복된 양상이다.
설명을 고치면 겨냥한 오류는 사라지지만, 다른 문항의 첫 출력이 바뀌어 새 오류가 생긴다.

| 단계 | 바꾼 설명 | 이 변경과 무관하게 바뀐 첫 출력 |
|---|---|---|
| v9 | D | 같은 첫 출력 60/96 |
| v11 | T2 | 장소를 측정값으로 읽는 오류 증가(held-out v27) |
| v12 | T3 | 집계 지어내기(m05) |

**현재 아키텍처에서 해결할 수 있는가:**
- **측정값·반환 대상 혼동:** 해결 가능하다. 계약 설명으로 7 → 0이 됐고, 새 필드나 코드 보정이 필요 없었다.
- **조건 계층 변경:** 공통 코드로는 해결할 수 없다. 측정값 추출이 안정된 모델과 묶인 조합으로만 성립한다.
  qwen3:8b에서는 해롭다(③). 아키텍처는 그대로 두되, 채택 단위를 "모델 + prompt + 코드"로 정해야 한다.
- **집계·factor 지어내기:**
  - 현재 계약에서 코드는 factor가 질문에 근거가 있는지 확인할 수 없다. 개념에는 `text`가 있지만 factor에는 근거 표현이 없다.
    근거 문자열을 쓰는 검증은 재질의의 집계 단계에만 있다.
  - 설명만으로 다루면 문구가 바뀔 때마다 다른 문항에서 다시 나타난다.
  - 코드가 확인할 수 있는 근거(질문 안 문자열의 존재)를 factor에도 요구하려면 **계약(표현) 변경**이 필요하다.
    질문 정규식이 아니라 모델이 적은 근거를 문자열 사실로만 확인하는 방식이다.
- **qwen3:8b의 통행량 ↔ trip 혼동:** 설명으로 줄지 않았다(4 → 5). **모델** 문제다. 이 모델을 기본으로 두는 한 남는다.

**무엇이 더 필요한가(우선순위):**
1. **평가 자료와 판단 방식.**
   - v11과 v12의 결론은 각각 한 문항(v27, m05)에 달렸다.
   - prompt 변경이 매번 몇 문항의 첫 출력을 바꾸므로, 20–50문항 셋의 단일 문항 기준은 문구의 우연을 판정한다.
   - 범주별 비율을 추정할 수 있는 규모의 평가 자료가 필요하다. 그리고 그 오차를 반영한 사전 등록 기준이 필요하다.
2. **계약.** factor의 근거를 코드가 문자열 사실로 확인할 수 있게 하는 표현이 있어야, 설명 문구에 의존하지 않고 지어낸 조건을 막을 수 있다.
3. **모델.**
   - qwen3.8:27b는 이번 범위에서 측정값 추출이 안정적이었다. 통행량 ↔ trip 0, 반환 대상 혼동 0(T3).
   - qwen3:8b의 혼동은 설명으로 줄지 않았다. 조건 계층 변경을 포함한 조합은 27b 같은 모델을 전제로 해야 한다.

## 5. 유지한 것과 바꾼 것

- **유지(v1 책임 분담):**
  - LLM은 grounding으로 의미를 표현하고, 코드는 계약 검증·합성·컴파일·실행을 맡는다.
  - 새 grounding 필드, Tool 직접 선택, 질문 정규식 추가, 조건 자동 삭제, 질문별·모델별 분기는 없다.
  - 재질의 1회, 연도 없는 날짜 정책, 업체 위임·직접 재계산 기준, 복구 정책은 그대로다.
  - 조건 계층(질문 표현으로 날짜·유형·상태를 확인하는 기존 코드)의 권한 정리는 후보 코드로만 있고 기본 경로에 들어가지 않았다.
- **기본 실행 경로:** 바뀐 것 없음.
  - prompt 522aa3b1, 현재 코드.
  - CLI GeoFlow 기본 모델 qwen3:8b와 timeout 300초(grounding_v11에서 평가 기준과 맞춤).
  - 사용자 `--model`·`OLLAMA_MODEL`·timeout 지정이 우선한다.
- **보존:**
  - 후보 브랜치: `grounding-v12-t3`(T3P), `grounding-v12-t3c`(T3PC)
  - 기준 태그: `grounding-v12-baseline`
  - 이번 결과를 본 뒤의 셋 지위:
    - 측정값 대조 셋: 개발용
    - v10 held-out: 개발용
    - 새 최종 검증 셋: **미사용**
